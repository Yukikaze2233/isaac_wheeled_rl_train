## 调度顺序和模型继承是两件事

现有调度依次运行 recovery → speed → terrain → jump → stepjump，但恢复、高速、地形和跳跃各自从 flat 分支初始化，随后优先恢复各自旧检查点；stepjump 继承 jump。因此当前 REC 模型没有因为 speed 曾经训练过，就自动获得高速能力。

候选改为一条明确的学习谱系：

```text
flat → recovery 正常端点 → speed 联合接续 → terrain 联合接续
                                      → jump 联合接续 → stepjump 联合接续
```

每次接续保留父模型的 actor、critic、Adam 和 RNG；在同一个策略上训练新增能力，旧技能继续混采。专项旧模型独立保留，不能将各专项成绩相加作为最终模型成绩，也不能将几个 ONNX 直接相加得到综合策略。全状态恢复等值仍需真实 worker 调用原生 `verify_learning_state_restore` 验证；目前的 CPU 封存审查不替代该验证。

## 已实现的谱系与预算候选

`integrated_lineage.py` 只做只读准入和额度计算，不启动训练、不写账本。首个 speed 来源必须是指定 REC 正常 15000 actor 端点的最终完整封存；后续域必须继承同联合谱系、同原始 REC 来源、已正常完成的父域。故障恢复只能使用本联合谱系最新自有封存，拒绝历史独立分支、SHA 不匹配、未完成父状态、同消费时钟不同权重及学习时钟倒退。

新联合学习时钟从实际新增 actor 更新计算。旧 speed／terrain／jump 已消耗的工作全部保留在原账本中，不能计作新联合模型已经学过，也不能退款。10 次 critic 适应照计消费，部分完成的适应只恢复余数。各域原 20000 和总 121000 上限不变；剩余额度不足时不通过增加预算或复用旧 actor 时钟伪造足额课程。候选没有新增能力 gate 或自动 qualification。

## 恢复完成率的记录修正

当前 `full_chain_success` 是瞬时状态比例；旧 lesson 累计计数经过 rollout 内 24 帧平均，其端点差不是整数结束回合数。54 组的混合成功数包含 L0／L1／L2，不能作为纯 L2 倒地自起链完成率。

本轮在原生 `record_outcomes` 的整数计数上新增 rollout 后记录，使用现有 TensorBoard writer 的 `RecoveryOutcomes/<lesson>/ended`、`successes`、`failures`、`collection_timeouts`。只在每次更新后读取一个 3×4 整数张量，不增加物理子步逻辑。零结束回合时省略成功率；同一 worker 两个端点的计数差才是对应窗口的真实分母。该记录代码尚未进入 Kaiser 运行源，不能用它补造当前历史 L2 完成率。
