## 调度顺序和模型继承是两件事

现有调度依次运行 recovery → speed → terrain → jump → stepjump，但恢复、高速、地形和跳跃各自从 flat 分支初始化，随后优先恢复各自旧检查点；stepjump 继承 jump。因此当前 REC 模型没有因为 speed 曾经训练过，就自动获得高速能力。

候选改为一条明确的学习谱系：

```text
flat → recovery 正常端点 → speed 联合接续 → terrain 联合接续
                                      → jump 联合接续 → stepjump 联合接续
```

每次接续保留父模型的 actor、critic、Adam 和 RNG；始终用同一个actor训练新增能力并复习旧技能。每个4096环境batch包含该域任务与复习任务，场景分组不建立独立网络；已学能力要在最终同一checkpoint上复核。专项旧模型独立保留，不能将各专项成绩相加作为最终模型成绩，也不能将几个ONNX直接相加得到综合策略。全状态恢复等值仍需真实worker调用原生 `verify_learning_state_restore` 验证；目前的CPU封存审查不替代该验证。
