# V5 SCUT35：可测量观测、200/50Hz 与分批回收

## 硬件反馈边界

用户确认可获取：六电机角度/转速、电机电流、IMU 角速度和加速度。
没有确认被动膝编码器、气簧位移/压力传感器或轮地接触传感器。
V5 的膝是被动输出，四个主动腿根部编码器和机构几何可以用于推算膝角与气簧长度；
轮子自身旋转角不是气簧长度的独立几何坐标。由行程和曲线得到的气簧力是模型估计，不是实测力。

## Actor 接口

入口 `scut_observation.build_scut35` 只接受编码器、IMU 和命令，不接受仿真气簧、接触、地形、根部速度。
单帧 35D，MLP `[256,128,64]`、ELU，六动作。排列遵循 SCUT V14 的 command-first 28+7 形式：

| 分组 | 维度 | 来源 |
|---|---:|---|
| 速度命令 | 3 | 上层 vx、vy、yaw；普通轮式行走 vy=0 |
| 高度命令 | 1 | 上层目标高度，乘 5 |
| 角速度 | 3 | IMU，乘 0.5 |
| 重力方向 | 3 | IMU 姿态融合估计 |
| 电机相对角度 | 6 | 编码器与标定零位；轮角两维固定为 0 |
| 电机转速 | 6 | 编码器速度，乘 0.1 |
| 上一步动作 | 6 | 已发出的 policy 指令 |
| 命令上下文 | 7 | normal、三个保留零位、jump 请求、请求跳高、请求后的计时 |

命令上下文不包含真实接触驱动的 phase，不包含台阶类别、高度或距离真值。
策略电机顺序为 `L_joint1, LL_joint1, R_joint1, RR_joint1, L_joint3, R_joint3`；
环境在施力前显式映射到已有控制器顺序。电机角度必须先转换为关节输出端 SI 单位并完成零位标定。

气簧移动副仍用于仿真内部动力学。真实接触、根部速度/高度、被动关节等只服务于 critic、奖励与验证；
critic 为 81D，不导出到部署模型。电流反馈可服务于保护和后续载荷估计，不为凑维度直接输入 actor。

## 时基与初始化

计划 `contracts/v5_scut35_v1.json` 继承完整技能清单：物理 200Hz、策略 50Hz、decimation=4，
24 步 rollout 对应 0.48s。PPO 初始 LR=1e-4、adaptive KL、gamma=.99、lambda=.95、初始动作 std=1。
腿位置动作 scale=.25，V5 的机械限制、电机力矩边界和气簧研究模型仍按自身模型配置。
这是 SCUT 风格网络/时基/PPO 适配；奖励与门控仍为 V5 版本，不声称完整复刻竞赛训练配方。

35D 单帧与旧 230D 历史策略不兼容，本轮从头训练新网络；旧模型和优化器作为历史批次回收，
不在接口变更后冒充 exact resume。第一阶段只验收已训练的站立能力，避免用尚未训练的行走/转向案例阻塞从零训练。
同一新合同的后续批次仍完整恢复 actor、critic、优化器与成功更新计数。

## 分批回收

`sync_chassis_batches.py` 在训练继续时，发现已结束的训练块、评测和阶段汇总，逐批打包、回收并验证 SHA256。
它不改变运行中的冻结训练源码。每批有独立 manifest；未通过评测的模型明确标为 candidate。
`watch_chassis_artifacts.py` 仍负责整轮结束后的最终完整归档，两者使用独立输出目录。

```bash
python scripts/sync_chassis_batches.py <launch-receipt.json> --output reports/<run>_batches
```

同任务手动续训使用已回收批次的 `contract.json` 和 `model_final.pt`，通过 `train_chassis.py --resume`，
从 checkpoint 恢复完整训练状态；跨任务按课程迁移，不能混淆为同合同续训。

## 扩容与耗时

`benchmark_chassis_capacity.py` 顺序测试 512、1024、2048、4096 环境，统计真实 PPO collection/learning 时间、
显存峰值和可用 RAM。内存不足时停止扩大，仅管理该工具启动的探针进程。
每任务的实际耗时依赖验收何时通过；配置上限不是收敛时间承诺。估算应包含采样、PPO、初始化、双种子评测与导出。
