# 历史课程失败的因果复盘与V6改进依据

日期：2026-09-28。范围：历史冻结配置/源码、同协议行为评测、最新P0两臂TensorBoard与最终验收；本次未训练、未修改奖励或执行器。

## 结论

历次失败不能用一个原因概括。最强证据指向：**课程实际训练分布偏离目标能力、已会能力缺少有效保留、部分训练成功定义与功能验收不一致，以及基础退化后仍进入更复杂阶段。** 旧跳跃还有可定位的奖励/相位问题。当前P0则表现为多目标适应中的姿态与静止改善、高度响应和前进跟踪退化；具体主导奖励项仍待受控实验确认。

没有证据把全部失败归结为训练不够、网络太小、探索消失、阈值太严或新机械轴向。新轴向资产尚未用于这些历史训练。实机动力学辨识很有必要，但不能解释同一仿真资产下从会到不会的全部变化。

## 2. 实际训练的是低速，任务名字却仍叫高速

V5.6为各速度组统一设置初始0.5m/s上限；70%采样frontier、25%easy、5%完整任务域，已有高速能力因此大部分时间没有按原速度得到保留。V5.7的6500次日志中，`forward_2`实际命令均值约0.365m/s、`forward_3`约0.357m/s，对应实际速度约0.386/0.383m/s。策略对采样命令的误差约0.10m/s，并不代表它练过2–3m/s。

V5.4又存在明显采样倾斜：所有高度任务合计24/65权重，普通单个速度组仅1/65。应审查每个能力实际得到的速度×高度×持续时间覆盖，不能靠组名、组数或episode计数判断课程覆盖。

V5.8把已有能力直接放回真实完整命令域，并将固定奖励与难度调节分开，取得局部恢复；它并未完全成功，但支持“保留真实行为覆盖比保留一个任务标签更重要”。新课程应从对应技能阶段开始覆盖完整目标域，以斜率、扰动、组合复杂度调难度，给旧能力保留实际命令和足够稳态驻留时间。

## 3. 课程改变了多个学习条件，策略很难保留已有解

V5.2名义学习率5e-5，首块实际adaptive LR峰值3.844e-4；原腿动作std约0.023–0.028，被抬到0.08。首次平地阶段又没有实际anchor保护，回归18→0未触发停止。奖励、探索和分布同时变化，无法把后续退化只归给某一项。

V5.7的自适应逻辑在速度/转向失败后同时降低height level，进而改变命令范围、采样混合和高度奖励核/倍率。5000→6500次，45组中最宽等级从9组增加到41组，最紧等级从25组降至1组；value loss同期上升。critic没有完整看到每组隐藏奖励等级，这是非平稳目标/价值混叠的具体来源，但日志相关性尚不足以证明它是唯一原因。

V5.7动作std随训练增大，不能说探索坍缩；固定1e-4也不能笼统说比旧学习率始终高数倍。新课程应冻结奖励语义，把难度状态和任务上下文明确化，每次诊断只改变能解释的变量，分别记录actor、critic、Adam和探索状态的迁移方式。

## 4. “训练成功”有时没有要求机器人真正完成动作

旧接触恢复阶段，airborne/landing记录了大量success，但完成条件主要检查接触、姿态、高度与相位，没有要求水平速度收敛。同块仍出现约0.34m/s速度误差和约20m漂移。“落地接触保持”与“落地站稳”在实现中没有等价。

V5.9阶段执行是monitor模式：评测失败会被记录，但预定预算完成后仍进入下一阶段。接触与跳跃训练因此承接了已退化的基础能力。这个机制解释失败如何传播，不解释最初为什么开始退化。V5.6和现在V6的保护停止已改善此问题，不能说所有版本都没有门槛。

此外，“50%复习”随着旧任务组增多被稀释：stand份额从flat的2.0%降到contact约0.42%，三个新接触任务各占16.67%。新阶段保留比例需要按行为族设置下限，不能只看复习总比例。当前V6合同已加入相应保护，但实现了保护不等于学习已通过。

新课程必须把速度、姿态、高度、漂移、持续时间共同纳入相应技能完成条件；物理安全终止、训练奖励和最终验收各司其职。稠密reward或success计数上涨不能自动晋级。

## 5. 旧跳跃已有稠密奖励，但奖励过程仍有漏洞

冻结V5.9跳跃源码有三类问题：

- 稠密参考随接触触发的物理phase/time变化，而35D actor及81D critic没有完整这些任务状态；同一命令时刻不保证面对相同过程目标。
- PUSH结束后未离地仍可停留在释放高度平台，持续获得高度收益。站在该平台并不等于完成COM释放。
- 过程跟踪使用base高度/速度，达成又包含整机COM升高；同时等待去抖后的FLIGHT才记录释放COM，丢失早期上升段。

最后跳跃块三个任务合计528183次takeoff_timeout，success、有效airtime和COM rise均为0，但仍有约3.1–3.3 reward/s。这证实大量尝试没有产生有效腾空，且不跳也有持续正收益；不能单凭正reward证明它比正确跳跃回报更高或是全局最优，也不能排除探索和控制可达性问题。

当前已改为命令时钟参考、限时PUSH、COM过程量与首离地采样。这些历史缺陷不能拿来解释当前没有跳跃样本的P0。后续还应检查jump critic是否得到必要的释放/相位历史，并将参考轨迹的可实现性与RL探索可达性分别验证。

## 6. 最新P0：宽核改善静止，但高度和速度仍然变坏

A/B从同一750完整checkpoint独立恢复，各100次优化（10critic-only、90actor），LR7.5e-6；训练分布为四高度×静止/0.5m/s前进，共8等额组，没有yaw复习。B同时放宽高度精度核10→30mm和静止速度精度核0.03→0.15m/s，不能拆分两项的因果贡献。

305mm静止点，两个评测seed均值：

|指标|source750|A|B|
|---|---:|---:|---:|
|实际高度mm|329.51|350.19|351.21|
|平面速率cm/s|12.38|1.18|0.57|
|两seed各自最大漂移的均值m|2.323|0.224|0.113|

四档静止高度命令跨度60mm，A/B实际只变化约7mm，响应斜率由源约0.218降到约0.121/0.117。B降低了精度核饱和，改善静止平移，却没有修复高度响应。完整`forward_05`回归的速度误差约0.101→0.195→0.327m/s，支持前进跟踪恶化，并非仅因长扫描提前触边。

不能把6→1都叫yaw遗忘：多个旋转项yaw误差反而下降，失分主要是高度变差，部分反向yaw也退化。两臂actor更新KL均值约0.0065/0.0068；腿侧95%限幅饱和为0，最坏轮侧低于0.018%。这些不支持“根本没更新”或“普遍电机封顶”，也不验证旧资产和包络正确。

当前高度奖励除了窄核，还有31.6mm尺度宽核和不饱和平方成本；不能声称整个高度奖励没有梯度，更不能把解析导数当成PPO参数梯度。TB显示高度分项变差、姿态/静止分项改善，与多目标权衡一致。到底是某项权重、动作可达性、继承策略还是优化路径主导，仍未由单变量干预确定。

详见归档的`reports/v6_asset_review_20260928/failure_ab_causal.md`及对应TensorBoard统计摘录。

### 高度—速度联合过冲诊断（待执行）

将“静止高度上漂”和“前进速度/高度同时超调”统一立项，暂不认定二者只有一个根因或存在单向因果。现有P0是分叉对照，不能把source→A→B当成同一策略连续训练轨迹。retained100、source750与A/B还涉及恢复/奖励历史，不能把横跨这些点的方向性变化当成“每次更新必然升高”的证据。

已有的排除边界：

- B静止平面速率由源约12.38cm/s降到0.57cm/s，高度却由329.51升到351.21mm，因此“只是跑得更快把机身抬高”不足以解释所有样本。
- 稳态前进的`stand_precision/stationary_speed_precision`不激活；静止核不是该段过速的直接即时奖励项。但静止/前进共享actor参数，静止组更新干扰前进组仍是可检验假说；B也同时改变了高度核，不能据此排除间接作用。
- `diagnostic_curriculum.py::diagnostic_contract`将`command_transport.enabled_fraction=0`，旧`usb_transport.enabled=false`。该下行队列保存PC计算后的六轴力矩，不保存上层速度命令。冻结代码与本地探针支持旁路设计，后续仍需运行时输入/输出相等断言；不能用“旧速度命令FIFO积压”直接解释本轮名义P0。
- 当前奖励分项及KL不足以判定“critic对速度过拟合”或“某项隐性奖励超速”。critic不直接产生部署动作，若有影响，应通过训练中的价值误差、优势估计和更新方向给出证据。

按成本和辨别力分三组实施，**保持35D/81D与原MLP结构，不先改奖励或继续训练**：

|编号与机制假说|诊断与必须记录的量|判读与下一步|
|D1 命令/策略输出/执行链偏置或耦合|同物理合同、初态、命令轨迹对source750/A/B确定性回放；先305mm下静止/±0.5m/s，再扩已有四高度。记录原始命令、slew后命令、actor实际输入、六维均值与实际执行动作、腿角目标/实角、轮速目标/实速、PD请求/限幅/下行输入输出力矩及时间戳、pitch/高度/vx。断言名义P0下行输入输出相等；同一观测只改变速度或高度命令，另测策略输出敏感性|策略目标已偏高/偏快则转D2/D3；目标合理但实际偏离则先查控制映射、气簧与执行链。离线换命令仅证明网络映射敏感性，不能冒充物理反事实。发现配置/旁路异常先停归因并修工程问题|
|D2 腿/轮输出及完整回报的共同权衡|冻结权重，在受限仿真比较源策略、新策略、源腿＋新轮、新腿＋源轮；准确反馈实际施加动作为下一拍previous_action。记录高度、速度、姿态、力矩、几何及所有reward分项/折扣回报；另用可实现的正确跟踪轨迹与过速/偏高轨迹，在同一冻结奖励下复算|新腿＋源轮仍上漂会削弱“只有速度抬高”解释；仅轮侧交换改变两者提示执行耦合。混合策略可能离开各自训练分布，须交叉核实，不能作为单独因果证明。正确行为完整回报更低时定位抵消项；若更高则转D3，不臆称奖励付费超速|
|D3 价值误差与静止/前进跨组更新干扰|采集同策略rollout但先不执行optimizer step，按静止/前进×高度分桶比较V预测、独立较长窗口回报/正确bootstrap、TD残差、优势符号与分布；在同一归一化规则下分别计算组别策略损失梯度及其对腿/轮目标输出的方向投影，记录样本数、截断和终止掩码|只有系统性V误判/优势方向异常，才将critic列为主要候选；只有静止组梯度确实推高前进目标等证据，才支持共享参数干扰。现有KL/std不是这些量的替代；需要训练验证时再做单变量、同预算对照|

归因交付必须分别写“已观察、支持/削弱的假说、未辨识项、下一项干预”，不以一个相关系数宣称共同根因。旧资产回放解释旧P0，新资产G0/G1另行验证，不在归因中同时切换机械模型。新增PPO探针须独立明确预算后执行；只读分析、回放与训练更新分开记账。所有诊断曲线使用现有TensorBoard，JSON/轨迹只承担复算和来源证据。本节为实施清单，以上D1–D3尚未执行。

## 7. 从华南虎、复旦学习什么

|上游方法|本项目应吸收的原则|不能直接移植的部分|
|---|---|---|
|华南虎完整闭链与整腿real2sim|先核对整套执行链，联合辨识两电机带结构的响应|关节阻尼、气弹簧曲线、电机上限、延迟和硬件PD模式|
|华南虎稠密过程参考与分阶段核宽|每个动作阶段给出可实现、可见、能区分正确动作的目标|只复制核宽；P0已证明放宽两项本身不够|
|复旦腿长/高度目标与并联部署映射|把任务目标落实到可检查的腿构型、速度和力矩关系|串联相对膝角直接当本机第二主动轴编码器；照抄其Jacobian/气簧补偿|
|两家实际启用的配置|对照执行分支、命令采样及部署语义|把源码中存在的实验模块都当成发布方案已验证|

SCUT普通Flat配置并不是我们的多阶段自适应课程，且高度命令本身有范围；复旦的坐标与控制接口也不同。上游有效不能推导出复制其参数便能解决本机失败。

## 8. 新一轮的判断顺序

1. 新机械资产轴向、质量、闭链、气簧和可达性先通过检查；用户提供bag后按[整腿辨识方案](V6_REAL2SIM_IDENTIFICATION_PLAN_20260928.md)拟合并完成MuJoCo→Isaac回放验证。辨识解决sim2real差异，不替代仿真内课程诊断。
2. 固定资产/控制/命令/评测，比较低响应与可实现高响应轨迹的各项回报。若跟踪正确的轨迹总回报更低，再定位抵消跟踪收益的具体项；若更高，则优先检查探索、初始化与优化。不要直接宣布策略“钻了奖励空子”。
3. 在同合同最小完整目标域上比较明确迁移与重新初始化；奖励消融、复习采样和优化器继承分别做对照，不能一臂同时换资产、网络、控制和奖励。
4. 基础速度/高度/静止达到固定回归后，再加入转向、升降、接触、人工跳跃/台阶；持续保留已会能力真实命令域。阶段难度改变斜率、扰动与组合，避免再次长期压成低速。
5. 阶段完成必须有真实功能证据；未出现COM释放就诊断起跳过程，不靠继续堆最终成功奖或直接进入地形来等待自然解决。

尚未收到实机bag，因此本文不包含辨识数值、实机误差达标结论或新训练成功承诺。
