# PC反馈通信与运动复习候选

日期：2026-10-11。本文记录本地候选、验证边界与接续要求；不是已部署运行合同。Kaiser的source029/v26 speed训练未被本轮候选替换，已按用户指令于06:26确认停止。当前只处理本地证据与候选修复；归档完成及最新PT深层重读因SSH无路由尚未核实。

## 时序定义

策略50 Hz；仿真物理与PC反馈PD 200 Hz。策略周期不计作USB/CAN通信延迟。反馈采用完整传感器→主机单向路径先验40 µs–15 ms；下行采用主机→驱动路径先验40 µs–14 ms，加0–1 ms CAN相位，总路径不超过15 ms。二者都不是实测RTT；不能将往返时间直接作为两个单向时间。

启用比例75%，共享同一个环境激活抽样；丢包与突发丢包概率为零。抖动相关系数0.9，创新半宽20 µs；该半宽不是累积抖动的硬界。按真实时间重建亚物理步延迟，保持传感器时间戳单调；重用Isaac Lab的GroupedDelayBuffer/CircularBuffer，不另造环形队列。15 ms范围是工程先验，尚未用实机路径测量校准。

反馈缓存包含六轴位置/速度、IMU角速度与重力方向共18通道。actor、目标角解码、四次物理子步的PC PD和恢复控制读取同一延迟反馈。气弹簧、critic、reward与物理安全统计读取仿真真实状态。StepTaskSensors的合成加速度和ray仍是新鲜仿真值，不能宣称所有部署传感器/FSM链路均已等价建模。

下行使用phase_aware_hold_v1；物理步内的力矩脉冲是积分近似。轮侧速度相关力矩上限在实际施力速度处重新计算，并写回响应滤波的上下限缓存，避免历史响应越过当前轮电机能力。该更新不改变腿侧上限。

## 接续前的必要工作

诊断脚本新增固定反馈／USB／CAN相位参数；覆盖仅替换探针进程内的原生通信对象，不改变canonical合同或其独立预检。`--fixed-feedback-ms`是完整反馈单向延迟，`--fixed-usb-ms`是下行USB基础延迟，CAN相位表示每1ms周期中消费事件的位置，不能直接当作追加串行延迟。固定CAN相位0.5ms时，反馈／USB的0.04／0.04、2.5／2.5、7.5／7.5、15／14ms四点，下行事件延迟分别为0.5、2.5、7.5、14.5ms；报告同时保留真实消息保持年龄，后者不等于PD反馈闭环总年龄。

`--warmup-seconds 2`在相同2秒静站前史中持续推进反馈缓存及下行shadow队列，但消费者读取新鲜状态、物理收到即时请求力矩；到明确policy边界才切回延迟读取／输出，不用enable toggle。加`--cold-queue-at-handoff`仅允许固定时序，在同一边界prime/reset通信对象，其绝对时钟、物理状态、actor历史及响应滤波保持。旋转及停车窗按交接相对时间定义，预热后仍执行完整12秒测试。每个5ms物理步应推进5个CAN tick；初始0.5秒及接管前后窗口按物理步记录实际目标分支、请求力矩、力矩帽、返回／实发力矩、反馈时间戳和真实状态。68项CPU协议与反馈缓存测试通过。下面两个固定点已执行；其余固定点及相同2秒前史的热／冷队列配对尚未执行，不能据此发放部署资格。
