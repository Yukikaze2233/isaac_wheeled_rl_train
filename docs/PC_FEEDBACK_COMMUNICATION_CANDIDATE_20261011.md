# PC反馈通信与运动复习候选

日期：2026-10-11。本文记录本地候选、验证边界与接续要求；不是已部署运行合同。Kaiser的source029/v26 speed训练未被本轮候选替换。

## 时序定义

策略50 Hz；仿真物理与PC反馈PD 200 Hz。策略周期不计作USB/CAN通信延迟。反馈采用完整传感器→主机单向路径先验40 µs–15 ms；下行采用主机→驱动路径先验40 µs–14 ms，加0–1 ms CAN相位，总路径不超过15 ms。二者都不是实测RTT；不能将往返时间直接作为两个单向时间。

启用比例75%，共享同一个环境激活抽样；丢包与突发丢包概率为零。抖动相关系数0.9，创新半宽20 µs；该半宽不是累积抖动的硬界。按真实时间重建亚物理步延迟，保持传感器时间戳单调；重用Isaac Lab的GroupedDelayBuffer/CircularBuffer，不另造环形队列。15 ms范围是工程先验，尚未用实机路径测量校准。

反馈缓存包含六轴位置/速度、IMU角速度与重力方向共18通道。actor、目标角解码、四次物理子步的PC PD和恢复控制读取同一延迟反馈。气弹簧、critic、reward与物理安全统计读取仿真真实状态。StepTaskSensors的合成加速度和ray仍是新鲜仿真值，不能宣称所有部署传感器/FSM链路均已等价建模。

下行使用phase_aware_hold_v1；物理步内的力矩脉冲是积分近似。轮侧速度相关力矩上限在实际施力速度处重新计算，并写回响应滤波的上下限缓存，避免历史响应越过当前轮电机能力。该更新不改变腿侧上限。

## 采样与来源

新增motion_rehearsal为显式opt-in，旧合同不自动采纳。speed中24个原基础平移/旋转组曾被同一联合vx/yaw采样器覆盖；候选恢复其中12个纯平移/纯旋转组，占9.5%，其余12个继续联合采样，占9.5%。组名、189总组数、总份额与其余课程保留；纯运动组拥有自己的命令，不再由heading或联合采样覆盖。

新通信配置必须与独立design/runtime预期一致，旧signal_delay/USB RTT随机化不叠加。精确固定评测只在对应固定通信profile行启用两向路径；未配置通信的clean行两向均关闭。随机先验探针必须显式声明interactive_unscored与training_domain_prior，不能冒充固定资格评测。

## 原生探针结果与限制

证据：`reports/pc_feedback_validation_20261011/native_clean002/report.json`和`native_prior001/report.json`。两次独立进程使用同一speed45500 ONNX、相同出生种子和相同原型源码哈希，三用例各两环境，12 s窗口；无PPO、无训练消费。clean001场景初始化超时，无行为数据，排除。

新时序组均未到达3–9 s稳定旋转或10.6–12 s停车观察窗，相关精度必须标为缺失，不能用零误差支付成功。无延迟稳定窗的平面速度：静止1.87 cm/s、正向旋转70.85 cm/s、反向23.82 cm/s；yaw角速度MAE分别0.311、0.318、4.936 rad/s。后两组高度MAE为80.17/56.70 mm。存活不等于运动质量达标；这些数据不证明旋转不对称的物理原因。

上述探针后又修正了实际力矩上限缓存及固定profile激活配对，故两次原生行为探针不覆盖最终候选字节。最终相关196项CPU回归通过（8.19 s），包括反馈缓存、消费顺序、固定profile、零丢包、命令拥有者及真实响应限幅；不能用CPU通过替代最终原生行为验证。现有策略直接移到新反馈闭环失败，不能直接满幅采纳，也不能单独归因于actor观测或PD反馈延迟。

随后从冻结`64b45cb94c69518d0660be83e39299098077e403`重做了两向先验的原生`native_prior002`；实际6/6仍在0.22–2.42 s提前终止，三个用例均缺失稳定旋转及停车观察窗，丢包为0，PPO消费为0。该回执覆盖力矩帽缓存和profile配对修正后的字节，但未组成最终源码的clean/固定延迟完整对照，因此不据此估计延迟贡献百分比，也不采纳到正式训练。

## 接续前的必要工作
