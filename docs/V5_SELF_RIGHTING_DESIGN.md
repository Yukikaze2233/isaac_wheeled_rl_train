# V5 起立／倒地自起：华南虎源码记录与后续设计

状态：**源码核对＋设计草案**。当前V5.4训练尚未加入倒地恢复任务或自起验收。
部署接口继续以[V54_DEPLOYMENT_INTERFACE.md](V54_DEPLOYMENT_INTERFACE.md)为准，六轴使用PC侧反馈控制和纯力矩输出。

## 1. 先区分三件事

| 行为 | 含义 | 与普通站立的关系 |
|---|---|---|
| 上电准备／低位起立 | 从可用关节构型插值到准备姿态 | 可以由关节PD脚本完成，之后交给RL平衡 |
| 不良构型／落地恢复 | 从腿位置异常、腾空或扰动状态重新稳定 | 可以共享normal策略，需要训练分布覆盖 |
| 完全倒地自起 | 从前趴、后仰、左右侧躺等机身姿态翻正并稳定 | 涉及世界姿态、接触支点和可达动作路径，不能仅由名义关节位或行程大小保证 |

因此，“公开部署的PREPARE不使用RL”和“单个RL策略可能具有部分恢复能力”并不矛盾。
不能把二者简单概括为所有自起都同源，或所有自起都不同源。

### 2.1 部署侧：四态控制职责

根路径：`src/controllers/template_ros2_controller/`。

| 入口 | 可直接确认的行为 |
|---|---|
| `src/fsm/state_machine.cpp:35-75` | 创建INIT、IDLE、PREPARE、RL；状态目标由外部请求管理，INIT有短暂启动处理 |
| `src/fsm/states/state_idle.cpp:22-33` | 所有关节输出力矩、Kp、Kd为0；位置字段跟随测量，不产生位置保持力 |
| `src/fsm/states/state_prepare.cpp:22-62` | 进入时记录前四个腿关节位置；按最大参考角速度向prepare目标插值，计算PD力矩；没有调用ONNX |
| `config/template_ros2_controller_parameters.yaml:125-143` | 默认prepare目标四维0，Kp=80、Kd=2、参考角速度上限1rad/s；这些是该配置默认值，不是V5参数 |
| `src/fsm/states/state_rl.cpp:19-22,50-68,241` | 单个35D→6D策略，尾部为normal常量`[1,0,0,0,0,0,0]` |

**索引纠正：** `src/template_ros2_controller.cpp:221-225`明确列出八关节：

```text
0 left_front1_joint    1 left_rear1_joint
2 right_front1_joint   3 right_rear1_joint
4 left_wheel_joint     5 right_wheel_joint
6 left_spring2_joint   7 right_spring2_joint
```

PREPARE中索引6/7的偏置是两个气簧接口，不是轮电机，也不是云台；轮4/5在该分支给零力矩。
V5实机只有六个主动电机，物理气簧不对应额外电机通道。

从源码可以确定的链路是：**IDLE卸主动驱动力 → 外部请求PREPARE → 关节限速插值／PD → 外部请求RL → normal策略平衡**。
PREPARE代码没有根据机身前趴／后仰／侧躺自动选择不同接触路径，也没有完整的倒地自起成功率证据。
因此应将它作为脚本起立基线，而不是直接宣称“任何倒地姿态都能靠该脚本起来”。
参考FSM职责也不等于直接复用所有低层输出分支；V5轮环必须按自身`0.2*(目标轮速-实测轮速)`等控制数学对齐。

### 2.2 训练侧：并非只有标准站立reset

根路径：`source/agent_tasks/agent_tasks/direct/wheelbipe/`。

- `wheelbipe_V14/cfg_utils.py:198-225`包含前／后向非标准腿构型采样：腿长0.14–0.36m、部分腿高度为负，根部初始高度0.25m，零主动驱动力矩窗口0.2s。
- `wheelbipe25_v3/env.py:5465-5523`将这些腿长／腿角做IK并初始化，随后设置零力矩计时及临时命令覆盖。
- 该地面重置的临时vx／yaw范围包含非零值，因而“恢复后启用普通策略”也不等于每次都只给零速站立命令。
- `env.py:2847-2924`在零力矩窗口内令目标位置／速度跟随当前状态，并清零主动effort；窗口结束后恢复策略控制。**启用的气簧模型仍施力，重力和接触也仍存在。**
- `start_reset_time=1.5`不能解释成“1.5s不检查终止”。该值还用于临时命令覆盖；`env.py:2811-2815`每步直接将`finish_init/start_reset`置true，实际终止还经过独立的状态机和持续判据。
- `wheelbipe_V14/env_cfg.py:1488-1528`的Flat-v1空中reset包含roll±0.1rad、pitch±0.2rad，并明确开启AirborneStateMachine；这是落地预训练，不能直接等同于±90°侧翻或180°倒扣覆盖。

这些机制可以产生“非标准腿构型／失稳 → 重新站稳”的同策略经验；是否覆盖完整倒地自起，仍要看具体初态、终止规则和实测结果。

### 2.3 recover槽位和upright奖励不能按名字推断

- `wheelbipe25_v3/env.py:1789-1799`中`recover_state`是恒False的零张量；布局有recover名称，不代表模式生效。
- 旧`standup`阶段与对应reward分支在该文件中处于注释状态。
- `upright_gate`主要用于门控跟踪奖励，不等于独立的自起控制器。
- 仅使用`g_x²+g_y²`时，正立`g=[0,0,-1]`和完全倒扣`g=[0,0,+1]`的值都是0，无法区分正倒。
- V14部分旋转平移变体还会重写七维上下文；不能把某个槽位非零直接解释为recover。

## 3. V5机械条件与当前策略的区别

用户确认髋可以连续旋转，相对膝角存在机械限位。电机前后安装位置不改变连杆拓扑。
对闭链而言，大腿根输入与曲柄根输入需要协调；只转一个输入并锁住另一个，可能改变相对膝角并触及膝／气簧边界。

本模型在名义构型上做了一个纯几何检查：将左侧`L_joint1`与`LL_joint1`同时增加0/90/180/270/360°，
其余内部相对坐标保持不变，最大闭合坐标残差约1.13µm；左膝raw角保持0.4rad，气簧压缩保持56.893mm。
这说明协调的整腿转动不必消耗相对膝角／气簧行程。它只验证闭链几何，不验证穿过机体／地面的可行性或翻身动力学。

当前V5.4仍有三项软件边界：

1. 普通fall逻辑会在机身翻至90°及以上时立即终止，非轮接触也有终止条件，无法直接采到完整倒地恢复过程。
2. actor腿位置目标为`q₀ + 0.25*clip(a,±3)`，覆盖名义位附近±0.75rad，**不是全圈目标覆盖**；机械continuous不等于策略已探索全圈摆腿。
3. 当前资产禁用自碰撞，执行器／传动仍有研究先验。大范围旋转实验需核对碰撞表达和驱动绑定，防止得到靠穿模实现的“成功”。

## 4. 路线A：先建立PC脚本起立／恢复基线

对外仍保留INIT／IDLE／PREPARE／RL四态，恢复尝试可作为PREPARE内部的有界子流程。
全程使用PC反馈算力矩、DM模式A `control_torque`；脚本目标不受actor的±0.75rad输出域限制，但必须满足机构与驱动约束。

### 4.1 普通PREPARE

从可支撑的低位或接近正立构型出发，记录当前模型主动轴角度，按限速／连续轨迹走向V5名义q₀。
PC计算位置PD；轮通道按明确的准备配置处理。完成判据包括关节跟踪、机身朝上、角速度和有效支撑，不只检查插值计时结束。
满足后进入RL普通模式，重新初始化上一动作、slew和jump时钟。

### 4.2 真正倒地的PREPARE恢复扩展

先用IMU把初态分成前趴、后仰、左侧躺、右侧躺及其他组合；每类独立验证：

1. 选择不越相对膝／气簧边界的支撑构型。
2. 协调根部两驱动，使腿移动到可产生翻正力矩的支点；需要时结合左右差动或轮驱动。
3. 依据有符号机身朝向和角速度反馈推进轨迹，接近正立后转入普通PREPARE。
4. 超时、无进展或机械异常时有界退出，不能无限重试。

具体方向、角目标、速度、允许支撑部件和轮扭矩必须由各姿态的接触仿真／台架结果确定。
髋360°有利于寻找支点，但不能单凭这一自由度保证侧躺可恢复；也不能笼统断言只有人形才需要多接触规划。
训练用的零力矩释放窗口不等于实机每次恢复都必须先卸力跌落。

## 5. 路线B：可选的单策略倒地恢复训练

这是后续实验设计，不向当前训练热修改环境或观测语义。
先保持35D尺寸和normal上下文，尝试扩大同一站立目标的可恢复状态域；**独立恢复任务／实验不等于最终必须部署第二个模型**。

### 5.1 初始状态与过程

- 分桶覆盖低位、前趴、后仰、左右侧躺及组合姿态；从实验开始就覆盖各类已验证可达初态，不用小倾角冒充倒地覆盖。
- reset时只设置一次满足闭链、关节行程及合理地面接触的初态；运行中不写姿态、不施加外部扶正力。
- 同时采样零速度站立、正常运动和扰动恢复，保持正常能力回归。
- 阶段难度调节初始角速度、外扰、摩擦和恢复时间要求；按姿态类别独立统计，不靠总平均成功率掩盖某类永远失败。

### 5.2 稠密目标

- 翻正采用有符号目标，例如`r_up=(1-g_z)/2`，正立为1、倒扣为0；必要时使用与discount一致的势函数进展项，避免往返摆动刷正向进展奖励。
- 高度／轮支撑目标在接近正立后逐渐增强，避免策略倒扣着顶高机身获取站立奖励。
- 同时约束角速度、动作变化、实际力矩／功率及不符合任务设计的接触；成功要求翻正、恢复支撑并持续稳定。
- 若恢复任务在相同可见状态下要求另一套互相矛盾的目标，应通过上层命令或版本化上下文表达，而不是隐藏任务差异。

### 5.3 终止、动作域与合同

- 恢复episode允许任务定义的倾斜姿态及支撑接触，设有限恢复时长；机械越界、闭链失效和非有限状态仍立即判失败。
- 不全局删除普通运动的fall／非轮接触判据，也不一概放开所有碰撞。
- 审计脚本基线是否确实需要超出当前actor目标角域。如果需要，动作域／解码要作为**新合同**训练并验证，不能仅放大clip后继续使用旧ONNX。
- 默认不启用未训练的recover槽位。若未来决定使用该槽位，虽维数仍为35，也属于语义变更，必须与新模型和部署实现一起版本化。
- 当前训练和部署中的PC力矩控制、编码器坐标以及电机包络仍需一致，不能靠额外力矩或绕过行程限制获得恢复成绩。

## 6. 对照验证与交付

在相同初态、摩擦、扰动和驱动模型下比较：普通PREPARE、分段反馈脚本恢复、候选RL恢复。
逐类记录成功率、恢复时间、最终姿态／高度、支撑持续时间、位移、力矩饱和、膝／气簧余量和闭链残差。
恢复过程的必要支点移动与恢复后的站立漂移应分开计量，不能把完整翻身过程直接套进站立0.1m驻留窗口。

首版实验可把“5s内恢复、随后稳定1s、机身倾角≤10°、高度误差≤10mm”作为**待验证候选判据**；
最终范围和阈值依据任务要求及物理验证冻结，现有V5.4普通技能验收不因该实验而放宽。

后续部署交付应包含：可恢复初态集合、明确不支持的姿态、脚本参数／模型及合同SHA、状态切换条件、
PC控制频率、驱动侧映射和曲线、失败退出行为、同初态对照报告。代码存在、能回到关节q₀或ONNX导出通过，都不能代替自起验收。
