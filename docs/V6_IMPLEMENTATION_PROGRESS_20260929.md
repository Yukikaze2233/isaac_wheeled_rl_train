# V6 新资产与 real2sim 实施记录

本轮已经执行离线辨识与新资产检查，不是新的正式训练成绩。网络保持 actor35 / critic81、MLP 256/128/64、ELU、六动作。正式 S1–S6 仍须等执行器模型、课程合同和验收入口冻结。

## 华南虎方法的实际复用

依据[系统辨识原文 §4.2](https://bbs.robomaster.com/article/1942489?source=1)与固定源码 `b8ff79f3df855faf9dc92f4a282bd80c42649466`：轮侧拟合摩擦/阻尼，腿侧在架空、完整并联机构中重现预设轨迹和闭环，再对比真机曲线。此源码快照提供执行器和限矩函数，没有发现可直接调用的 bag→整腿参数优化器。

因此复用本项目已有 MuJoCo 闭链回放，整理为 `scripts/identify_pair_dynamics.py`；同侧髋与膝驱动共同仿真，保留轮子、被动关节、重力和气簧。每段只在起点使用实测初态，其后自由积分，未逐帧写入实测位置。PD 160/2.5 固定，每 1ms 重算；50Hz 目标直接取录制值保持，不调 PD 补偿动力学误差。

## 新机械资产

独立目录 `model/纯底盘_v6_232mm/urdf`，新 CAD root 已是 X前/Y左/Z上，不再额外旋转。主动腿轴相对旧模型反号；q、dq、力矩一致变换，保持功率/虚功。总质量 13.886kg，RR_link2 使用源 CAD 的 0.084kg，尚无单独称重证据。

保留 232mm 全伸、80mm 行程气簧与原静态拟合；新资产显式修复不合法惯量并记录研究先验来源。19 刚体、16R+2P、6 外闭环。独立单环境 PhysX 的固定底盘小摆检查已运行；这项检查不代替实测轨迹的跨引擎复现、碰撞域验证或硬件验收。最终数值和哈希以资产内验证回执为准。

关键反证是**1秒实发力矩输入回放仍有明显偏离**，平均分段角 RMSE 约1rad。强 PD 闭环会抑制模型误差，闭环曲线比较接近不足以确认真实被控对象。静态共同方向力矩也与 CAD 重力预测存在系统残差。扭矩比例消融、静载/摩擦与编码器参考零位应分别检查，禁止把候选直接发布到训练。

IMU 以运行段每100个样本诊断：左/右相对水平平均倾斜约3.23°/2.48°；IMU坐标→CAD安装对齐仍未独立确认。架台不是完美水平常量；该记录只用于有出处的重力姿态对照，不允许任意旋转曲线去追求重合。

## 轮侧发现

轮输出单位只做一次15.8转换，速度环工程选择仍为P0.6。现有运动摩擦/阻尼拟合不能解释低速停走；引入固定静止阈值虽改善部分±0.2rad/s段，仍漏掉短暂滑动和持续停走，且右轮滑行有退化。不能把拟合的动摩擦截距叫已辨识静摩擦，更不能将速度控制增益当物理黏滞阻尼。

详见 RMCS `docs/zh-cn/artifacts/wheel_speed_v2/scut_real2sim_audit_20260928/README.md` 与对应脚本/JSON；静止阈值搜索范围是损失平坦区域，不是统计置信区间或物理硬界。

## 启动与容量

新增独立设计表逐字段比较、精确子步时钟检查和执行计数，详见 [预检实现](V6_PREFLIGHT_IMPLEMENTATION_20260929.md)。离线测试已验证 20 次物理步/新反馈 PD 对应一个50Hz策略目标，USB关闭不能再被计为USB功能验收。

20,000 环境入口和 480,000样本/更新、48,000样本/minibatch 已接通。新资产容量 probe 使用 `--validate-scene`，只运行物理场景，不建立 PPO runner；随机化/通信关闭值明确冻结，仅检查名义场景容量。它不证明完整 PPO、最复杂地形或随机化开启时也能保持同样吞吐。正式8500更新预算与E0预算不因此消费。

## 继续实施的验收顺序

1. 完成新资产实际20k场景容量和冻结回执。
2. 用扭矩输入回放与静载残差排除参考端、零位、受力和损耗错误；两侧、不同构型均验证。
3. 将通过留出的最小物理模型接到 Isaac，复现同一bag轨迹；再冻结实测支持的不确定性集合。
4. 完成新S1–S6的可执行课程/奖励与独立设计表，做带 PPO 的20k容量、E0和正式训练。当前未用旧合同冒充这份新课程。
