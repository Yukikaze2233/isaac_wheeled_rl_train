# V6人工触发技能：Policy、Reward与课程评审计划

日期：2026-09-26。用户已授权制定并接续补救课程；本页保留设计依据。
实际接口、COM参考定义、门槛与验证见[实施说明](V6_MANUAL_REMEDIATION_IMPLEMENTATION_20260926.md)，部署状态以启动回执为准。

本机没有前向地形传感器；操作员可以按键请求上台阶、下台阶及跳跃。
因此主线应为**人工意图 → 可部署命令／参考状态机 → 条件策略 → 六轴PC力矩控制**。
此前`v6_emergency_v1.json`中的自动前探仅保留为仿真研究对照，不是本方案的实车前提。

## 1. 结论与优先级

1. 先修正评测环境和统计语义，再修复名义站立、速度跟踪与加减速。
2. 保留MLP主干和6D动作／PD边界；利用35D里的预留上下文表达人工技能与参考，并建议增加1维可部署加速度参考，形成36D待评审ABI。
3. 上台阶采用人工STEP模式；训练覆盖按键时机误差，不输入真实障碍高度或距离。
4. 跳跃重点解决**请求已触发、蹬伸却没有造成离地**，不是只把请求计时提前。
5. 先验证执行器约束内的真实蹬伸轨迹；参考／初始化冷启动优先，物理外力辅助是独立待批对照。
6. 将基础能力保留升级为阶段推进硬门槛。预算到期但门槛未过时，停留在当前阶段。

## 3. 华南虎可借鉴的机制与证据边界

参考：`scut-wheeled-legged-rl@b8ff79f3df855faf9dc92f4a282bd80c42649466`。

- `JumpTakeoffStateMachine`提供弹道参考、请求／phase、分窗口奖励和force／velocity两种辅助，支持辅助概率／力幅渐退。
- `peak_height_bins`是带概率的分箱采样；源码另有按训练进度变化的高度区间。不能把它描述成已核实的“成功率50%逐bin晋级”。
- V14观测上下文含normal/stair/slope/recover/jump/height_target/state_time。主配置总状态机和若干helper开关为关闭，具体启用必须落到实际任务类。
- `StepUpStateMachine`修改高度命令并保持，不直接修改前向速度，也不自动发跳跃命令。
- base与腿轮质量、base COM启动随机化可参考。独立惯量事件的启用情况与“质量变化时一致缩放惯量”不同。

采用的是机制和可验证的接口，不把存在一个类等同于其在普通V14训练中全部启用。
两家网络参数量相近也不能单独证明容量足够；先解决已有证据指向的任务、控制与评测问题，再做网络消融。

## 4. Policy与可部署输入

### 4.1 推荐主方案：36D动态参考接口，保持MLP主干

主干保留`256/128/64 ELU`、6D动作、50Hz policy、200Hz PC反馈以及当前输出端力矩边界。
同侧髋／膝驱动仍是两根机身参考的主动轴；前膝、后髋，外部链传动1:1。

拟议上下文（索引从0开始）：

| 索引 | 拟议语义 | 来源 |
|---|---|---|
| 0–27 | 现有指令、编码器、IMU、上一动作 | 沿用原输入 |
| 28 | normal模式 | 人工命令状态机 |
| 29 | manual terrain mode：0普通、+1上阶、−1下阶 | 操作员请求，不由地形真值分类 |
| 30 | 激活技能的`h_ref-h_start`，非技能时0 | 可在PC重放的参考生成器 |
| 31 | 激活技能的`v_z_ref`，非技能时0 | 同一参考生成器 |
| 32 | jump request | 按键接受后的锁存请求 |
| 33 | 请求跳跃目标，×5 | 命令参数，精确高度定义在合同中版本化 |
| 34 | 技能请求后的计时 | PC单调时钟／仿真策略时钟 |
| 35（新增） | `a_x_ref`，参考纵向加速度 | 有界命令轨迹的解析导数，不是仿真真加速度 |

这是**36D新观测ABI**，不是与旧35D无条件兼容。迁移第一层的旧35列，并将新启用的29–31列和新增第35列权重置零，
验证普通稳态模式输出与父actor一致；新合同重新训练critic和optimizer。源／目标ABI与零列初始化必须写回执。
不得将真实接触phase、terrain高度／距离、root真速度作为这些字段的来源。

增加`a_x_ref`是因为同一个vx目标可能处于加速、匀速或减速；单帧actor看不到上一速度命令。
如果reward开始追随动态俯仰参考，policy也必须知道决定该参考的加速度，避免再次引入隐藏目标。
35D版本保留为“仅命令轨迹＋原姿态reward”的对照，不靠复用含糊字段来凑维数。

参考首先按命令时钟生成，训练与部署共用相同代码。若引入落地检测驱动的切相，应使用
同一编码器／IMU估计器并先做误检／延迟验证；PhysX接触可以用于critic、reward和评测，不能直接替代部署输入。

critic可增加相对落点、任务进度、真实COM状态与实际随机化参数，layout与维数由合同显式生成。
这是降低隐藏任务状态造成的价值估计方差，不要求实机提供这些真值。

备选只在消融证明必要后评审：扩展观测或短历史／循环策略。原建议“35→41D”所列新增字段实际超过6维，
还重复了已有请求／目标／计时，不能直接按该数字改网络。

### 4.2 人工STEP模式

推荐“STEP模式键＋W/S推进”：先建立越障高度，再由操作员给定有界推进速度；释放／取消后恢复普通模式。
不根据不可见的真实台阶位置自动给最优触发时机。训练中随机化按键提前量、接近速度、姿态及误触发／取消。

- 先验证3／6／10cm，再独立验证15／20／25cm；保留两种失败指标：未越线与越线后未稳定。
- 上阶预备高度在0.36／0.40／0.43m等已声明域内做机械／碰撞检查，再选档。
  “+5cm保持2秒”是对照参数，不能未经本机验证就作为所有台阶的通用解。
- 推进段有明确vx参考和加速／退出时间；不是外加前向力，也不扩大轮力矩包络。
- 缺乏前向感知时不承诺自主分类台阶／墙。堵转只可由可部署反馈估计并允许人工退出；真实几何真值仅用于训练判定。
- 同一人工请求要覆盖不同真实高度与触发距离，避免策略依赖“按键总是在距边缘精确某处发生”。

已有本机对照发现0.10m前探时机壳先碰撞、0.50m前探能提前触发但旧actor仍未通过高台阶。
它说明准备时机和姿态必须验证，不代表无传感器硬件可以使用该探测器。

## 5. 跳跃：先验证能蹬离地，再优化完整过程

### 5.1 触发与参考

1. 先建立计数链：request → accepted → preload → push → 双轮离地 → apex → landing → stable。
2. 正式评测保留正常站姿后按键的完整过程；预载姿态出生只作专项冷启动，不替代整任务验收。
3. 人工请求在可部署姿态／反馈条件满足时接受；0.3–0.5s稳定检查是候选参数，不能把2s当现有请求门。
4. 统一跳高定义。建议新任务将目标定义为**质心相对离地点的飞行上升量**，冷启动档0.03／0.06／0.10m，
   对应理想释放速度约0.77／1.08／1.40m/s；还必须同时通过真实双轮离地、间隙和落地要求。
5. 原V5.9的base高度增量案例保留为独立legacy回归，不能混同上述COM高度并直接横比成功率。
6. 预载／蹬伸使用连续参考；在当前40Nm腿限幅、轮包络、膝40–110°和气簧80mm行程内验证动态可达性。
   已通过的静态载荷／高度检查不等于已证明动态跳跃可达。

优先用真实电机／气簧驱动的脚本参考或轨迹优化证明至少能获得第一批无辅助起跳样本。
若参考本身无法在模型力矩／速度／行程边界内离地，先修改参考或明确物理缺口，不能继续盲目调reward。

### 5.2 分相reward建议

以下为待短测定标的初值；所有稠密项按每秒密度乘dt，事件奖只发一次。

| 段 | 主目标 | 初始处理 |
|---|---|---|
| 预载 | 跟踪h_ref、v_ref，保有支撑与可用气簧余量 | 保留现有三次参考，初始h/v权重各3；先检查是否真跟上 |
| 蹬伸 | 建立正向COM速度／地面反力冲量，进入无辅助离地 | h/v跟踪；新增释放速度与真实离地事件的过程诊断 |
| 腾空 | 合理收腿、姿态与角速度，防止单纯伸腿骗base高度 | tuck权重1→2做单独对照；弹道高度主要用于测量，避免奖励不可控的空中COM加速 |
| 落地／恢复 | 平面减速、落点、姿态、高度回收和支撑稳定 | 增加限时1–1.5s的平面速度／姿态／相对落点塑形，合计量级先与起跳h/v相当 |
| 完成 | 真离地＋目标高度＋落地稳定 | 保留当前+5基线；比较有限增幅，不直接叠加+50淹没过程奖励 |

蹬伸窗口内torque、power及动作平滑可从原尺度降至0.25做消融，但只降低软代价，机械／驱动硬边界保持。
不能把全局motor/wheel惩罚统一归为失败原因：先记录分相回报、实际力矩、饱和及正向功率。
原代码已经通过支撑phase关闭了起跳／腾空的普通高度跟踪；落地阶段普通高度与jump落地参考仍需核对冲突。

腾空时允许合理姿态偏差，保留倒扣、机壳冲击、非有限值、闭链／膝／气簧硬失败。
不采用“FLIGHT所有姿态和机械失败都不终止”。起跳失败仍有有界超时，期限由参考预载＋蹬伸时间及余量确定；
当前“1.86s退出”应先解释为真实蹬伸失败，不靠无限延长回合消除失败标签。

### 5.3 冷启动与助跳取舍

推荐顺序：

1. 闭链有效的预载／蹬伸中间状态初始化，逐步增加正常站姿开始的比例。
2. 由真实执行器可完成的参考轨迹生成少量示范，做技能条件BC／warm start；普通模式保持回归。
3. 若前两项仍无起跳样本，单独评审有限时段外力辅助对照；持续保留无辅助环境，最终能力只由辅助完全关闭的测试认定。

不把root速度直接写成目标速度作为默认训练方案。注入1.2m/s本身就对应约7.3cm弹道上升，
足以掩盖6cm量级任务的起跳失败。华南虎确有velocity写入分支，也有force分支，两者的动力学含义不同。
如批准force辅助，应记录冲量／做功和辅助占比，先验证衰减到0后的离地率；辅助成功不计入无辅助课程晋级。

当前actor探索std是否过窄需要记录。专项复制候选可单独比较std下限／熵项，不能在运行中的父actor上静默重置探索参数。

## 6. 加减速、域随机化与防遗忘

- 恒速、加速、减速、反向、驻留分别统计。加速度profile有固定曝光配额，不依赖恒速前沿先晋级。
- 从上一命令参考平滑采样下一段，同时保留真实从静止启停；不以仿真真速度为实车上不存在的命令生成输入。
- 高幅值池从原5%做有界提高的对照，例如15–20%；同时记录实际给到actor的vx、dv/dt、驻留时长和饱和。
- 启停过程不能只用“稳态命令保持至少1s”的筛帧统计来判定加速能力；逐段计算跟踪、减速距离及停止漂移。
- 质量／COM模块及PhysX读回验证可复用。先保持独立惯量倍率1.0，质量改变时完整惯量张量一致缩放。
- 每段保留约50%名义机械对照，USB clean／jitter独立配对；不要同时改变全部随机化、奖励和优化器再作单因果结论。
- 跳跃专项保持至少50%跳跃，后续地形／混合段以行为池分配明确复习份额，避免降到每组32环境后继续遗忘。

## 7. 验收与队列：从monitor升级为硬推进门槛

### 7.1 两类门槛分开

**工程门槛：**资产／ABI、几何、reset、碰撞、观测目标一致性、预算与checkpoint恢复正确。
环境异常标为invalid setup，先修复并重跑；不能把首步穿透当策略能力失败，也不能通过关闭机械终止掩盖问题。

**能力门槛：**

- 修复阶段完成前：站立vx MAE≤0.03m/s、10s漂移≤0.10m、高度MAE≤0.01m；正反0.5m/s与正反1rad/s基础用例通过。
- 每次技能交接：保留固定54项clean／USB中的父模型已通过项；高幅值尚未通过项继续如实列出。
- 起跳按请求接受率、无辅助离地率、释放速度、COM顶点分布、真实轮间隙、落地速度／位移、稳定时间逐项验收。
- 越阶按接近、越线、双轮支撑、姿态／高度稳定、离开障碍后2s恢复分段统计。实际0.15／0.20／0.25m分别验收。
- 发布时每主要条件至少20回合、两个独立seed、辅助关闭；成功率目标≥90%，并报告样本量。

训练可以有“离地”“越线”等宽过程事件奖励，但不能把宽事件当作正式完成，或用辅助成绩推动无辅助能力晋级。
暂定bin增加曝光以无辅助宽完成率≥50%为依据，正式发布仍用严格落地标准；二者不能同时都叫“晋级门槛”。

### 7.2 执行规则

1. P1允许从当前不合格V5.9继续做修复；不能要求它先通过修复目标才允许开始修复。
2. 后续技能段须在基础门通过后进入。latest、段初、最佳保留候选分别保存。
3. 基础回归失败：回到本段合格候选，最多一次有明确改动的修复预算；再失败则停队报告。
4. 预算耗尽但技能门未过：保留已学技能和当前候选，停在该段，不能自动带着退化进入下一段。
5. 训练消耗、继承的实际模型谱系、失败分支消耗分开记账。旧V5.9消耗不当作新目标已合格。

### 11.2 旋转姿态：测量比“看起来合理”更重要

轮距约0.4373m时，2rps绕轴旋转的轮心速度约`(4π)×0.4373/2=2.75m/s`。
0.75m/s是误用了0.06m轮半径；旋转本身也有角加速、轮胎侧滑和陀螺／惯性耦合。

本机没有独立髋外展自由度，不能把视觉上的“张腿”直接解释成主动加宽轮距。
代表轨迹实测的机体系左右轮横向间距仍约0.4373m，变化主要来自俯仰、左右伸缩及前后错位：

- 地形段末+2rps：左右膝约45.5°／45.1°，前后轮错位约42mm；−2rps一侧贴近40°下限。
- mixed段1000的+2rps：左右膝约61.8°／60.3°，错位约21mm；−2rps约78.0°／82.9°，错位约36mm，平均俯仰约5.1°。

以上是每case一个代表回合、3秒后的采样，不是全回合总体分布。
应记录高度、姿态、膝／气簧余量、两轮前后错位和旋转中心漂移，不强迫所有转速用同一固定关节姿态。
固定的机体原点与轮轴中点诊断应分开，避免将参考点绕转和整车平移混为一谈。

当前reward本来就有pitch/roll指数与平方项、height、no_fork；“旋转没有姿态塑形”不符合源码。
真实质量不对称可能影响姿势，但RR_link2的0.84kg与LL_link2的0.084kg应核实来源／称重；±10%随机化不能修正10倍名义质量错误。

### 11.4 统一的动态参考边界

命令生成器输出一个版本化参考对象：

`mode, reference_phase, elapsed, vx_ref, ax_ref, yaw_ref, h_ref, vz_ref, apex_goal`。

policy观测、reward、任务日志使用同一份参考。参考phase首先由命令时钟和已知轨迹参数决定；
真实运动phase另用于物理诊断和验收。当前actor使用请求计时，而jump reward使用接触驱动的phase计时，
两者可能出现随出生／接触而变化的偏移，这一差别必须明确校核。

评价应始终保留“目标参考”和“实际响应”两条轨迹，按预载、蹬伸、腾空、落地分别积分误差及奖励贡献。
仅有episode总回报不足以解释哪一段停滞。

### 11.5 平移：速度轨迹＋可解释的倾身参考

1. 用有界加速度／jerk生成`vx_ref(t)`，同时给policy其导数`ax_ref(t)`。
2. 初始前倾参考以`theta_ref≈atan(ax_ref/g)`为起点，经本机动态可达性验证后限幅／滤波。
   前倾正方向须按模型控制坐标定义。0.6m/s²对应约3.5°，并不必然伴随数厘米下沉。
3. pitch指数项和pitch平方项统一追踪`theta-theta_ref`；不能只改其中一项，让另一项继续惩罚正确倾身。
4. 匀速／驻留时`ax_ref=0`，恢复严格高度、直立与零速要求。加速阶段仅适度软化软代价，硬边界不豁免。
5. 速度reward保留精跟踪核，并对大误差加入明确的宽核或Huber型伴随项，保持“离目标更近”可区分。

现有速度指数项先把误差裁到±1m/s，超出后该项为常数；已有二次项仍提供回报差，故不能说完全没学习信号。
要通过受控消融检查大误差区的相对收益是否太弱，而不是不加分析地把所有姿态惩罚关掉。

日志增加：统一滚动正方向后的左右轮共模／差模目标与力矩、轮速、饱和、vx/yaw误差和速度命令敏感性。
先做同一传感器状态只改变vx请求的离线policy响应检查，再用真实闭环确认，区分“网络不响应命令”与“驱动力到地面后失效”。

### 11.6 跳跃：已有轨迹框架，但要堵住过程目标的漏洞

当前V5.9并非只有最高点reward：已有三次预载、匀加速推蹬、弹道和落地h/v参考。
下一版要完善其训练条件和动态评价，而不是重复添加同名项：

- **预载**：在可达域内跟踪下蹲高度与负垂向速度，记录是否真正完成预载。
- **蹬伸**：以正向COM释放速度建立为主目标，辅以高度轨迹；记录冲量和实际做功，而不是单纯追求更大力矩。
- **释放窗口结束**：如果仍未离地，不能继续在“已到释放高度”上持续拿满高度奖励。
  当前参考末端会保持释放高度和释放速度，因此需要专门比较“原地伸高”和“真实起跳”的分相回报。
- **腾空**：弹道参考是完整任务的评价轨迹；控制目标主要是收腿、姿态和着地准备。
  不把飞行中的COM速度改变当成可由内部关节任意完成的控制任务。
- **落地**：用一致的支撑估计／参考时序生成缓冲轨迹，奖励降落速度收敛、平面减速、姿态及落点稳定。
- **全过程**：实际双轮离地、COM上升、落地稳定三项联合认定，避免伸腿抬base或外力助推冒充自主跳跃。

稠密不等于一定好学：远离参考时过窄指数核也会近似饱和。需检查每段误差分布，再使用宽核／Huber伴随项与合理初始化。
PPO利用的是回报差／advantage，不是直接对奖励曲线中的仿真状态求导；不能用“有曲线所以必然有足够优化梯度”代替实验。

### 11.7 接续修复的第一批实验

同一个最新完整父模型、同一物理资产、相同预算与固定评测，按以下顺序：

| 实验 | 唯一主要变化 | 要回答的问题 |
|---|---|---|
