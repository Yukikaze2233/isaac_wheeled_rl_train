# 1 kHz 通信与执行时序：现有 bag 可证明什么

2026-09-29。本报告只读已有 NPZ、质量报告和归档控制器日志，没有重新读大 MCAP、操作硬件或改训练合同。统计使用每包全部 `phase=2` 采集段，包含保持、单侧/双侧运动与零电流段，没有挑选此前辨识通过的短窗。原文件路径、SHA256、精确分母与统计在 [observations.json](../reports/v6_transport_bag_audit_20260929/observations.json)。

**结论：可以量化主机执行省略、反馈缓存重复和主机观察到的反馈年龄；不能从这些 bag 唯一辨识 USB/CAN 的真实丢包概率或单程传输延迟。** 因而 1 kHz 概率遗漏/延迟抖动可以作为显式稳健性随机化，但不能把其自选概率命名成“实测真实丢包率”。

执行省略由覆盖开始/完成事件前后的完整 executor 计数证实：前四包累计 Skipped 始终为 0；P0.4 的四次增量全部落在 active 内。其 **4/630000≈6.35 ppm（0.000635%）** 是主机执行省略观察值，不是通信丢包率，也不是伯努利独立同分布模型已验证。

P0.4 已记录 active 的端点跨度是 629.594837 s，对应 629596 个名义时隙；实际 629592 行，差值恰为这 4 次省略。剩余计划尾部约 404 ms 未写入恢复后的 bag；归档日志证明程序执行至完成，但主机随后重启、录包未正常封存。**630000−629592=408 不能全部记成通信丢包：其中4是执行省略，约404是未持久化尾部。** 该包有655个周期超过1.5 ms，但只有4个超过2 ms及4次日志确认的执行省略；较长周期后可能通过较短周期追上计划时钟。

五个 active 段的 recorder tick 都连续，队列/发布 `dropped_samples` 计数都为0。右腿整个文件的7个tick缺口含首次使能失败、等待与复位间隔；成功 active 的671420行无缺口。不能把等待遥控器的几十秒当成随机丢包。`dropped_samples=0` 也不保证 rosbag 已将尾部持久化，P0.4 就是反例。

## 反馈：缓存重复有明显侧别与时序结构

分母是完整 active 的相邻记录对数 `N−1`。重复定义为所选轴 `feedback_sequence[i]==feedback_sequence[i−1]`，不是位置/速度数值不变。年龄定义为 `control_steady_ns−feedback_steady_ns`；两者都是主机时钟。只统计当前受试两轴，轮试验中失能 DM 的较慢轮询不混入轮反馈统计。

右腿不是稀疏独立长串断流：两轴同时重复44233拍，重复事件相关系数约0.796，重复间隔中位为10拍；RH有45539次、RK有44922次相邻重复事件恰隔10拍。它表现出明显的约10 ms调度/采样结构，**不应直接拟合成两个独立8%命令丢包器**。该记录确实有约8%的1 kHz观测沿用旧反馈，可用于验证反馈缓存保持的建模，但原因可能包括反馈生成、总线接收、主机回调与采样相位，现有数据没有将它们分离。

另一反例是轮P0.6：虽然反馈重复约0.7–0.9%，但两轴主机回调序号总增量为635723/639807，均高于629999个采样间隔，且有11361/14032次单拍序号增加超过1。这是“期间收到多个回调，但记录只保留最新值”的证据；`sequence jump>1` 不能解释为总线上丢失了对应报文。所有受试轴均无序号倒退，统计年龄无负值。

## 提交缺项与真实交付不是同一件事

三轮包每个已记录 active 行均有 `tx_kind=1`、有限的轮力矩 payload、正的提交时间；提交时间没有重复行。两个轮轴的同一0x200提交时标相同，不能由此声称它们具有两个独立的链路丢包过程。

两腿包各轴都有 **1343/671420≈0.200%** 的 `tau_frame_api` 非有限行，但提交时间仍每拍更新。左包原始MIT审计已将全部1343行认定为周期性 **0xFC使能心跳**，`unexpected_frame_rows=0`；这是有意用系统帧代替扭矩帧，不是随机丢包。右包同样数量/时序的缺项与之相符，但本轮只读该包导出的字段，没有右侧逐字节MIT审计，不能夸大为已逐字节证明。

`tx_queued_steady_ns` 是 host 调用板卡 SDK 后记录的提交时间，SDK不提供在此bag里的CAN交付ACK；`feedback_sequence` 是主机接收回调序号，也不是驱动命令ACK。五包 `record_time−submit_time` 中位约22–23 μs，只反映同次组件更新内“先提交、后录样”的顺序，**不能据此宣布USB单程只有22 μs**。反馈年龄同样包括电机反馈节奏、CAN、USB、回调与当前采样时刻，不能拆成纯USB延迟。用户给出的HS亚毫秒链路先验与这些观察不矛盾，但尚未由现有时间戳单独验证。

## 对新域随机化的约束

1. 保持三个独立含义：1 kHz执行/提交遗漏、收到反馈前沿用旧观测、成功交付的延迟抖动。当前执行省略约束明显不同于右腿8%的缓存重复，不能合成一个“loss”参数。
2. 若加入命令遗漏随机化，其分布应标记为**设计的稳健性假设**；缺ACK时真实发生概率、独立性与连续丢包长度均未辨识。丢命令时保持上次已交付指令，不能把其含义擅自变为零力矩；真实设备超时行为另有硬件语义。
3. 反馈保持可参照上表与约10 ms的共同事件，但不要把所有轴默认独立。若同时模拟固定反馈年龄、随机缓存保持和额外随机延迟，要明确队列/时钟次序，避免同一实测陈旧效应重复计算。
4. 可重放 bag 的执行间隔和反馈序号/年龄进行确定性验收，再做显式的随机压力评测。不能因为当前实测执行省略为0，就宣称真实链路丢包概率为0；也不能因为仿真加入更高丢包率，就声称已恢复电机真实曲线。

本次仅提供证据与语义边界，不改正在运行或暂停的训练、通信合同、电机响应参数。
