## 2. 运行要求

- 推理频率 **50 Hz**（周期 20 ms），单帧输入，无历史堆帧（history_length = 1）。
- 输入 `float32 [1, 35]`，构造完成后整体裁剪到 ±100。
- 输出 `float32 [1, 6]`（原始策略动作，需经 §5 解码后才能下发）。
- 编码器数值为**校准后的关节输出端 SI 单位**（弧度 / rad·s⁻¹），不是电机转子端原始值。

## 4. 关节顺序映射（易错点）

控制/编码器原始顺序（CONTROL_ORDER）：
`L_joint1, LL_joint1, L_joint3(左轮), R_joint1, RR_joint1, R_joint3(右轮)`

策略观测/动作顺序（POLICY_ORDER）：腿在前、轮在后：
`L_joint1, LL_joint1, R_joint1, RR_joint1, L_joint3(左轮), R_joint3(右轮)`

- 观测重排索引 `POLICY_FROM_CONTROL = [0, 1, 3, 4, 2, 5]`
- 动作重排索引 `CONTROL_FROM_POLICY = [0, 1, 4, 2, 3, 5]`
- 腿槽位（策略序 0–3）＝控制序 [0, 1, 3, 4]；轮槽位＝控制序 [2, 5]

## 5. 输出动作解码（必须执行）

原始输出 6 维不能直接下发，按以下步骤解码：

1. 裁剪：腿 4 维 ±3.0，轮 2 维 **±9.0**（`action_clip=3.0`，`wheel_action_clip=9.0`；2026-09-26 修订，初版误写轮 ±3——以 `policy.onnx.contract.json` 与 RMCS `action.cpp` 实现为准）。
2. 按 CONTROL_FROM_POLICY 重排到控制顺序。
3. 腿位置目标（rad）：`target = nominal[腿] + 0.25 × action[腿]`，再对当前 q 做包角归一（取最近等效角）。
4. 轮速度目标（rad/s，关节输出端）：`target = 10.0 × action[轮]`。
5. 将裁剪后的原始动作（解码前）回填到下一步观测的 22–27 维。

`nominal` 为 6 维名义关节姿态，取自交付包 control_prior，**不得用自定义站姿替代**。

## 6. 关节端控制数学（参考实现）

力矩均为**关节输出端**约定（功率共轭）；传动比、电流环编码由适配层负责，可用 `joint_to_drive_torques()` 以标定 Jacobian（6×6 满秩）映射到驱动器端，不假设恒等映射。

**腿（位置 PD）**：
`τ = clip(60 × (target − q) − 2.0 × dq, −40, +40)` N·m（kp=60, kd=2, 限幅 ±40）

**轮（速度 PD + 电机包络限幅）**：
`τ = clip(0.2 × (target − dq), −bound, +bound)` N·m
- 包络：电机侧速度 0→999.06 rad/s 线性 0.349→0 N·m（M3508 参考先验，非实测曲线）
- 关节端 bound = min(包络插值 × 减速比 11 × 效率 1.0, 3.84) N·m
- 低于包络查表下界的速度按 0 力矩处理（`right=0`）

## 7. 联调与验收流程

1. 校验 SHA（§1）。
2. 用 `io_fixture.json` 的输入对跑通 ONNX，比对参考输出。
3. 用 `v5_policy_io.py` 复算观测构造、动作解码、参考力矩，逐项对表 §3–§6。
4. 仿真内验证记录见交付包 `verification.json`；能力清单（27 案例 18 项通过，名义高度 0.305 m）见 `README.md`。
5. 本文档对应**平地移动/旋转/定高模型**：跳跃、横移、 terrain 能力未包含，对应观测位按 §3 恒值填写。

## 8. 已知边界

- 名义工作高度 0.305 m；模型验收域内高度命令即在此附近。
- 观测不含气弹簧维度：气簧长度是腿关节角的确定函数（并联约束），真机为无源机械件，无需估计、无需标定值。
- 轮力矩包络是参考先验（`curve_kind: reference_linear_prior_not_measured`），实车若实测包络不同，以实测替换并同步训练侧。
- ABI 冻结于交付包合同；后续版本（如带链路延迟训练的新策略）将另发交付包与新合同，不与本模型混用。
