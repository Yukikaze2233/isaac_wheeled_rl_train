# 第一轮 stand2000：结果与开源对照复盘

## 已完成的工程验证

第一轮为 v1 FrameStack + stock PPO，256 环境；先训练 100 次，再恢复模型和 optimizer 追加 1900 次。
北京时间 2026-09-11 01:46 完成，checkpoint、ONNX、来源文件和完成收据已校验回传。
这证明采样、更新、保存、导出和回传链路可执行，不等于物理模型或策略质量全部正确。

完整 event 文件最后 100 次更新（1899–1998）平均 reward 约 67.48，平均回合时长约 16.53 秒，
平均高度误差约 1.83 cm。不能把约1600次时的阶段性 reward 81 写成最终结果，也不能由
TensorBoard 的批次平均终止惩罚反推出逐回合失败时长分布。

最终 checkpoint 的一个固定初态确定性回放在 7.04 秒由 AABB 净空条件终止：
高度约0.283 m、倾角约24.3°、轮轴中心漂移约0.225 m。它没有触发35°倾角或0.18m高度条件。
这说明终止判据口径重要；不能因为某个 Termination tag 为零就宣称不存在失稳。

## 最高优先级：连续轮误导入为有限关节

canonical URDF 声明四个髋/轮关节为 continuous，但同时携带原始占位 lower/upper = ±3.14。
服务器实测导入后的 USD 和 PhysX 均使用了这些有限范围；回放中的轮角也停在边界附近。
因此第一轮不能作为正确连续轮物理下的性能基线。双轮平均接触力接近 mg/2 不能排除这个错误。

修复位于 `wheeled_world/assets/v40.py`：在 physics 初始化前，将这四个关节的 composed USD
限位恢复为无界，两膝只读核验原35–80°机械限位；初始化后读回每个环境的真实 solver limits。
PhysX 用精确 float32 extrema 表示无界，也可能返回 IEEE infinity；不能把任意大有限限位当作无界。

服务器多圈诊断中，两环境的两轮分别以正/负初速自由演化，实际展开转角均约19.79882 rad，
即3.15圈，和关节速度积分一致。PhysX 会回绕报告角度，因此裸终值减初值不是圈数。
原 CAD、URDF、资产清单及历史 run 均未改写；修复在仿真适配层实现。

## 对照复旦与华南虎：哪些结论成立

| 议题 | 源码事实及结论 |
| --- | --- |
| 硬限位/软限位 | 复旦 URDF 有物理 lower/upper；奖励把有限区间按中心收为97%，不是删除物理边界。华南虎部署 MJCF 同样有有限关节。我们应修复 continuous 语义，并避免额外软区夹紧和立即终止叠加。 |
| 高度可达性 | 按 v1 完整髋/膝动作盒、canonical FK 与轮圆柱接地求得直立双轮等高范围约0.29808–0.33877m，不是0.3136–0.3200m。v2 的0.5位置尺度已能覆盖0.28–0.32m命令；几何覆盖不保证负载下闭环跟踪。 |
| 目标与实际角度 | 有限刚度PD下实际关节角与目标不同。不能把目标FK范围直接当作实际高度硬限位。 |
| 腿探索 | v1 std=.2 与髋/膝 scale=.15/.10 对应初始目标标准差.03/.02rad，显著小于两家的常见配置。v2扩大scale为.5，保持当前网络与PPO起点，便于审查；不是完整复旦算法复制。 |
| 高度指数核 | `exp(-(e/.03)^2)` 在e=.02m处约.641，斜率绝对值约28.50/m；最大斜率发生在.02121m附近。因此2cm并非指数核梯度消失区域。PPO也不直接对物理状态上的奖励梯度反传。 |
| enhance | 复旦当前plane启用速度/yaw enhance，但它们是更宽的指数核减1，不是简单负平方。高度enhance函数存在，当前reward scales没有启用；不能说两家都已启用高度伴随项。华南虎确有高度平方项，但须按具体任务/状态的有效配置判断。 |
| critic | 复旦环境输出141维，再拼3维latent，critic网络输入144维。更多维度不自动意味着价值学习更快。 |
| 统计证据 | reward约100只是理想20秒回合的上界，不能解释为完成度百分比。批次平均不能证明某个惩罚项单独产生了效果，或确定所有晚期终止的共同原因。 |

## 第二轮处理顺序

1. 先修正实际物理导入，保留错误模型下的旧实验作为排错记录。
2. 用显式v2 profile取消额外动作缩窄和过早终止，接入已列明的开源基础机制；不新增alive bonus，
   也不根据未经证实的“2cm处梯度不足”直接叠加自定义奖励。
3. 分别训练平衡与平地行驶，在同一配置族下记录任务、种子、样本量及身份。不是只比较迭代数。
4. 域随机化、延迟、速度估计encoder以及真实链传动标定仍需后续明确实现与实验，不冒充已具备。

来源以本地上游源码为准：复旦 `plane/wheel_legged_gym/envs/base/legged_robot.py` 的
`_process_dof_props`、`_reward_base_height*`、`_reward_tracking_*`；对应的
`legged_robot_config.py` 与 `wheel_legged_config.py`；华南虎 V14 配置和继承的
`wheelbipe25_v3/env.py` 高度奖励及动作执行实现。

录制尝试在目标服务器的 RTX `scenedb` 启动路径崩溃，不能据单个native栈断定驱动版本就是根因。
它是画面输出的独立阻塞，不作为修改PPO或机器人奖励的理由。
