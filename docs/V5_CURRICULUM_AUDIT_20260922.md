# V5课程机制核对：当前运行与历史问题分开判断

核对对象：`v5-scut35-20260921T131715Z-a4ae54`，SCUT参考提交`b8ff79f3df855faf9dc92f4a282bd80c42649466`。
本文件核对“缺少辅助力/奖励调度必然导致跳跃卡死”等判断，不把源码中存在的实验组件视为所有任务都已启用。

## 当前真实合同

- `reward_profile = scut_v14_flat_v5`，`height_l1_weight = 0.0`。
- `phase_reward_masks`的ground只包含GROUND；TAKEOFF使用`FullTaskSemantics`的预压/蹬伸参考。
- 普通高度奖励在TAKEOFF和FLIGHT关闭，RECOVERY可恢复地面高度跟踪。
- 当前采用7个综合阶段，共享35D actor；速度档和地形档是阶段内采样组与验收点。
- 物理200Hz、策略50Hz、6144并行环境；每实际更新采样147456 transitions。

因此，“固定height L1惩罚与蓄力必然对抗”的前提不适用于本轮。
即使某项奖励存在冲突，也不能仅从一个权重推导PPO必然永久失败，需要比较完整奖励、相位和探索分布。
L1在非零误差处对误差的导数幅值不随误差减小；减小的是罚值。PPO的策略梯度也不是直接对状态误差求导。

## SCUT两类progression的实际状态

源码`wheelbipe_V14/env_cfg.py:365-464`确实定义了：

- `BaseVerticalAssistForceProgression`，160→80→0 N。
- `RewardWeightProgression`，按目标奖励门槛调整配置，最后恢复默认权重。

但同文件V14 Flat基础类为`curriculum = None`（476–477行）；已检查的公开flat、rough、
rotation_translation预训练`params/env.yaml`也为`curriculum: null`。
这证明它们是可参考组件，不能据此断言它们是当前公开基线必需且实际启用的训练机制。

实现细节在`manager/mdp/isaaclab/curriculums.py`：

- `window_size=64`会乘`num_steps_per_env=24`，得到1536项窗口。
- 每次非空重置批次调用追加一个批次平均奖励，计数加1，而不是每个episode分别追加。
- 配置中的`min_episodes=500`也乘24。
- 门槛读取`_episode_sums[reward_key]`，并按最大回合秒数归一化，不直接使用高度MAE。
- 阶段按阈值单向推进；不是任意误差下都能自动加权/减权的双向控制器。

移植应先明确统计单位和指标语义，不能把这些配置直接解释成“最近64个episode误差”。

## 160 N不能直接照搬

V5当前资产质量为14.642 kg，重力约143.638 N。160 N竖直外力已超过整机重力；
在没有其他外部向下约束时，它会产生净向上作用，而不只是减轻负载。
气簧是内部作用力，不能抵消这个整机净外力。减小法向载荷还会改变轮地牵引能力。

辅助力只能作为独立消融候选：按V5重量归一化，明确适用环境与支撑相位，限制持续时间，
在零辅助力下独立验收。奖励调度也应记录系数与窗口状态并随checkpoint恢复。
这些职责涉及采样、相位、恢复与评测，不只是新增一个奖励表达式。

M4的`stand_still_lin_vel`是速度惩罚，不是位移惩罚；当前已实现。M6/M7已在鲁棒阶段启用，

终止持续确认应以秒定义，结合当前50Hz策略换算，不能直接复制20步。
标准20秒回合最多1000个policy步，因此旧100Hz设置下的“638→1900”不能直接用作本轮目标。
延后终止可能增加episode length，但不自动改善姿态、漂移或成功率。

## v5.1建议顺序

1. 固定零辅助基线，补齐低/高高度保持的训练覆盖，检查静止和运动样本占比及分项奖励贡献。
2. 按case、相位和终止原因校准指标口径；阈值调整基于目标能力和物理依据，不为过门追随当前误差。
3. 对原始高度误差、存活和接触稳定性做分组窗口统计，消融性能驱动权重/采样调度，并持久化调度状态。
4. 只有弱起点探索确实受限时才比较重量归一化辅助力，最终零辅助验收；不把160N直接用于V5。
5. 增加中段容量与遗忘监控；发生退化先排查分布和优化，再通过受控网络规模对比判断容量。

这些是待验证改进方向，不构成“加M1–M4后所有问题全部有解”的保证。
