# V6 单束激光上阶、运动学站高与台阶跳设计

更新：2026-09-29。用户确认未来传感器为**单束前向距离，配合预设台阶高度**。本文件规定下一实施方案；尚未安装激光，也未完成RMCS技能接线，不是硬件发布回执。网络保持actor35/critic81、50Hz策略与1kHz PC PD。

## 1. 华南虎中复用什么

核对官方训练源 `b8ff79f3df855faf9dc92f4a282bd80c42649466`：

- [StepUpStateMachine](https://github.com/scutrobotlab/wheeled-legged_RL/blob/b8ff79f3df855faf9dc92f4a282bd80c42649466/source/agent_tasks/agent_tasks/direct/wheelbipe/state_machines/step_up.py#L28)在探测事件后提高`height_cmd`、保持一段时间，然后恢复用户高度命令。策略负责生成关节动作，状态机提供任务参考。
- [前向扫描](https://github.com/scutrobotlab/wheeled-legged_RL/blob/b8ff79f3df855faf9dc92f4a282bd80c42649466/source/agent_tasks/agent_tasks/direct/wheelbipe/wheelbipe25_v3/env.py#L210)从仿真轮心前方、沿世界-Z向地形投射；[时间差分](https://github.com/scutrobotlab/wheeled-legged_RL/blob/b8ff79f3df855faf9dc92f4a282bd80c42649466/source/agent_tasks/agent_tasks/direct/wheelbipe/wheelbipe25_v3/env.py#L826)给出前方地形高度变化。该输入不等同于实车单束水平测距。
- [高度计算](https://github.com/scutrobotlab/wheeled-legged_RL/blob/b8ff79f3df855faf9dc92f4a282bd80c42649466/source/agent_tasks/agent_tasks/direct/wheelbipe/wheelbipe25_v3/env.py#L508)存在腿长、root Z、减去raycast地形高度等不同口径；不能统称为实车编码器测高。

因此复用“探测事件→动态参考→保持→恢复”结构，数值按我们的几何和可达域确定。感知适配为单束距离与预设高度；不照搬0.15/0.25m探测阈值或把仿真地形真值传入actor。模块存在不表示其全部默认配置都启用，也不表示公开部署已有同等传感器。

## 2. 电机角度如何计算站高

每侧先将两个电机编码器按实测零位、符号与传动比映射到主动轴，再通过**完整闭链正运动学**求轮心在`base_link`中的位置`p_wheel_B`。相对膝内角不是膝电机角；不能把两主动轴作为串联髋膝直接套公式。共同转角控制摆腿，差动经闭链决定膝部形状。

设`g_B`为IMU姿态得到的单位向下重力方向。在轮子接触近似水平支撑面、有效轮半径为`r`时：

```text
height_if_grounded_i = r + dot(g_B, p_wheel_B_i)
```

这给出`base_link`原点到该侧支撑面的竖直距离，包含roll/pitch补偿；既不是欧氏腿长，也不是质心高度。双轮同平面可靠支撑时可融合左右结果。轮胎压缩、显著轮轴倾斜和坡面需使用实际接触几何/有效半径并计入不确定性，不能无限沿用固定半径近似。

RMCS已有可复用实现：`rmcs_rl/src/recovery_observer.cpp`第22–44行查`auxiliary−hip`闭链LUT并绕髋轴旋转，第140–147行计算上述高度。当前observer仅在恢复功能及标定配置就绪时实例化；不是普通RL已经上线的通用高度传感器。实施时提取/复用这段原生几何查询，供恢复和越阶共享，避免再造一套左右符号与LUT。保留独立的支撑有效性和时间戳；不要把恢复用的窄站高门槛复制到全0.23–0.43m越阶域。

必须区分以下输出：

|输出|可观测条件|使用范围|
|---|---|---|
|左右轮心相对位置、机构内膝角|有效编码器与已标定闭链|架空也可用；机械构型和激光安装几何|
|左右`height_if_grounded`|上述量加IMU姿态|接地假设下的候选站高|
|融合的站高与有效标志|已确认的支撑关系|抬升进度、支撑后的稳定判定|
|世界高度/相对原地面的高度|还需地面基准或外部估计|仅靠关节角不能得到|

架空或腾空时关节角不能确定真实离地高度；相同腿姿可整体被吊高任意距离。左右轮跨不同平台时不可无条件平均：保留每侧支撑面，按可信支撑侧使用；即使双轮均着地，简单均值也是相对两支撑面平均标高。壳体最低间隙另按壳体点计算。

## 3. 持续前推时的自动上阶

操作目标：启用自动越阶、选择已知台阶档位，遥控器持续给正向速度；有效距离到达触发域后自动提交一次STEP请求。人工按键提交同种请求。上阶结束并站稳后恢复持续前推，遇到下一独立台阶可再次触发。

```text
普通行驶 → 发现障碍并减速接近 → 提交/锁存STEP请求
        → 平滑抬高与跨越参考 → 落台稳定 → 恢复普通行驶/下一台阶
```

- 请求源只区别`manual/laser`，不改变策略维度。技能模式、参考高度、参考速度和开始/结束时序经现有35D命令上下文表达；不将距离、真值地形或接触相位偷偷塞入旧观测槽。
- 测距需有时间戳、有效标志、安装外参与姿态补偿。触发距离按轮/车体前沿位置、接近速度、参考抬升时间和已标定制动能力计算；不指定无实验依据的万能距离。
- 当前站高用于确认抬升进度，并计算激光发射点高度与光束方向；预设台阶高度用于选择参考。**两种高度分别记录**。
- 水平光束若高于台阶顶面，可能根本照不到台阶正面。安装时检查全站高/俯仰域的光束覆盖；倾斜光束还须区分地面回波。已知发射点高度和一个命中距离也不能确定台阶顶面，更不能区分同一命中点背后是台阶还是墙。自动模式适用于已知高度/形状的赛场区域，未知障碍不自动升级为可跨越台阶。
- 持续前推是操作意图，不是每周期新请求。请求锁存；忙时重复不重启参考时钟；完成后结合距离退出/重新进入、位置进展和下一台阶确认重新武装。连续两级不能仅靠相同距离阈值反复计数。
- 取消语义沿用技能流程：进入前可取消；已起跳/跨越时由恢复流程完成支撑，不能因松杆直接重置关节或相位。双下仍走RMCS原生失能路径。
- 单束无回波不等于下台阶，也不等于上阶完成；下阶仍按显式请求/已知场地流程，腾空与落台用可部署状态估计。

普通行驶与高度调整持续跟踪命令；上阶/主动跳跃使用请求与参考状态机；意外腾空/落地按实际状态恢复；倒地自起仍由现有R0关节轨迹与RL接管流程独立处理。

## 4. 原地跳、行进跳与台阶跳课程

用户新增目标：先训练原地跳与行进跳，再练基础台阶跳；**双级连续台阶跳是基础台阶跳通过后的特化补强课程**。台阶跳包含起跳面与落台面高度不同、有限落地区和连续两次起跳；已有滚行上阶成绩与同平面跳跃成绩不能代替。

- 第一级高200mm、踏面长**800mm**，覆盖此前双级设计的第一级0.6m踏面。
- 用户已确认：第二级在第一级上**再升250mm**，第二顶面距原地面450mm。旧“第二顶面250mm、再升50mm”口径作废，不能用于此专项。第二级踏面长度尚未新指定，现有0.6m仅作待核对设计值。
- 原有连续3×4cm、每级踏面0.6m的滚行上下楼梯保留，不被该双级替代。

**已发现旧双级几何实现缺陷，修复前不能计作该能力证据。** 旧合同`stairs_200_250`声明`stair_heights_m=[0.2,0.25]`，但`task.py::terrain_surfaces`仅消费`stair_rise_m`，硬编码3级与0.6m踏面。CPU实际物化得到的是4/8/12cm顶面，而非旧合同所写20/25cm；下阶亦同。当前通信候选刻意保留旧课程定义，未夹带地形修复。这一缺口必须在台阶修订中修复并对最终碰撞几何断言，不能只检查case名字存在。

教学顺序与验收：

|步骤|训练内容|独立验收|
|---|---|---|
|原地跳|已有3/6/10/15/20/25/30cm跳高与稳定落地|无辅助实际离地、顶点、姿态、落地后驻留|
|行进跳|已有行进命令，覆盖接近/释放/落地速度|起跳和落地位置、速度恢复、持续前进|
|单级台阶跳|从低台阶到200mm等目标；多种起跳距离、接近速度与站高|有效抬轮越过前缘，在顶面落稳而非碰墙后弹上去|
|双级特化补强|基础台阶跳通过后，先跃上200mm台阶，在800mm踏面内恢复/再接近，再跃上高250mm的第二级|两次独立起跳与落台，第二跳重置参考及成功事件记录；第二落台标高450mm|
|S6组合|自动/人工请求、连续前推、重复/取消、载荷/摩擦/时序组合|不重复触发同一级，不以一次成功顶替整段完成|

S4保留滚行上阶；S5按原地/行进跳→基础台阶跳→双级特化补强推进；S6组合验收。专项激活以前置技能的固定确认评测为依据，激活后的难度/辅助随已保存的课程时钟推进，不按单回合胜率来回切换。专项失败单列为“连续双级尚未达标”，不把已通过的基础跳跃重新描述成没学会。保留普通行进、站高、单级台阶跳和落地恢复的复习份额。

专项需独立标识课程配额、预算、父checkpoint与消费，不能直接均匀混进最初的跳跃采样池。总8500预算不因新增能力默默扩张；实施时重分S5/S6剩余配额并另封合同，若需要额外预算则显式修订。本文件不承诺原2000更新内必定学会所有新增任务。

800mm是踏面几何长度，实际可用恢复/再起跳距离还要扣除落点散布、轮缘和车体前后扫掠空间。先在已确认物理可达的单级构型中学200mm与250mm落台，再收敛到完整800mm连接段；预设几何相同但请求时机、接近速度和扰动由易到难。第二级增高250mm，以第一级支撑面作为本次跳跃基准，不能让策略把累计450mm误当一次起跳目标，也不能沿用只再升50mm的动作模板。

奖励沿用广域稠密项＋精核及动态参考，不靠只在成功时付分：接近段跟踪起跳区与速度，蹬伸段跟踪可达释放目标，腾空段约束轮缘净空与姿态，落台段约束顶面落点/冲击/支撑恢复，稳定后衔接下一请求。对每次跳明确起跳支撑标高、落台标高、额外净空和顶点口径；台阶高不能机械地等于平地身体顶点增高。每个事件成功只计一次，辅助样本不进无辅助验收。

## 5. 实施与验收清单

当前训练实现与台阶跳之间还有以下具体差距，不能通过只更换地形名字解决：

|实现位置|现状|台阶跳修订要求|
|---|---|---|
|`skill_curriculum.py`、`env.py`|jump绑定平地，step/stairs为另一mode；跳跃模块启用还依赖地形名|分开技能和地形身份，台阶场景确实启用完整跳跃采样/参考/奖励|
|`references.py`|腾空时间`2*v_release/g`、末端返回起始高度，假设同高起落|逐跳声明落台高差、下降段接触与参考交接，不把250mm跃台套同平面弹道|
|`rewards.py`、`env.py`|跳跃高度相对请求起点；地面查询随当前位置变化|保留世界系COM释放基准，分离世界位移、目标落台标高和当前支撑面站高；正确落台不能受200mm假误差惩罚|
|`full_tasks.py`|现有跳跃成功不核对指定平台、有限顶面和前缘净空|逐跳验证平台身份、落地区、轮/车体净空、支撑恢复；排除错误位置跳完再滚到终点|
|`training_schedule.py`、`env.py`|已有落地再跳与历史清零，但没有两级各自目标|复用真实恢复后再请求机制，为两次跳绑定不同起跳区域、落台标高及独立记录|
