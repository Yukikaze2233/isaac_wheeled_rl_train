## 2. 控制分工和时钟

本轮目标链路为：编码器/FK与IMU选择恢复路线 → 脚本产生协调连续参考 → 反馈翻正/捕获 → 可部署支撑估计允许交接 → 200ms模型侧力矩混合 → 纯RL零速接稳 → 继续站立、前进或转向。恢复后直接跳跃、再次请求恢复等复合链尚未纳入这54项。

- 脚本承担大范围翻身，RL学习脚本实际到达状态的接稳与后续运动。**若某初态每次都在脚本阶段失败，它没有该恢复链的有效PPO样本；增加PPO更新不能改善这段脚本。** 应修复脚本/观测器或明确未通过域，不能将其改称“精度尚未达标”。纯RL已经接管后的跟踪精度不足才按相应证据描述。
- 同侧髋、膝主动轴协调；连续共同圈数、带符号轴方向与闭链分支必须保留。主动轴无位置止挡不意味着相对膝或气簧无限行程。脚本连续目标不在每个物理tick改用最短角差，避免跨π时反转原恢复路线。
- 当前训练原生路径为恢复FSM/参考200Hz、下层PD/P及力矩混合1000Hz、RL目标50Hz。参考与反馈控制各有时钟，不靠整体加快状态机实现1kHz PD。冻结脚本总时限为8s，含初始释放段。
- 脚本与RL各自保持目标，混合的是模型侧力矩；下行延迟/丢包、执行器响应及输出约束在共同输出路径作用一次。上一动作槽反映实际参考的混合结果，释放/失败时为零。这里实现的是训练端语义，尚未证明与RMCS逐拍等价。
- 脚本轮侧平衡根据IMU俯仰、角速及轮速生成等效轮速目标，仍经过轮P0.6、4.5N·m约束及共同输出链；不另行绕过执行器模型施加轮力矩。其增益及支撑判定仍需完整姿态和扰动物理验证。
- 编码器反馈用整数圈数维护连续角，FK、恢复参考、脚本PD与原生RL的PD共享同一反馈时序；未跨圈时保持原始反馈逐位一致，不把USB延迟反馈与真值交叉更新。PREPARE使用当前V6求出的0.305m质心平衡几何及`q_command=q_geometry+tau_static/160`参考；几何初态与补偿命令分别保存，补偿仍是名义静力模型，并非新实机辨识。失去支撑且倾角超过70°持续150ms时，脚本最多重新选路一次，8s总时限不重置，混合或RL阶段不回退脚本。
- 新V6已验证的轮侧响应贯穿脚本、混合和RL；腿侧未qualified仍标工程先验。重力、气簧机构力矩、闭链耦合与止挡接触连续存在，悬空bag或PD整定不等于全构型负载模型已辨识。

历史RMCS `rl_controller.cpp` 的 `pd_divisor=rate/200` 会在非计算tick重发旧力矩；旧 `inspect_v5_activation.py` 直接写effort、旧Python观测器含V5零位，均不能认证本轮实现。本轮使用正式环境单物理步输出链和V6闭链/LUT，**不要求先修改RMCS，也没有离线接管状态库前置**。未来硬件迁移再单独核对C++参考、时钟、混合与失能行为。

## 5. 稠密奖励、随机化与分项验收

纯RL接管段复用冻结的广域＋精核站高、姿态/角速、速度/静止、动作连续性和功率等成本，没有为恢复另加未经定标的奖励基形。脚本/释放/混合段即使计算了诊断reward，也不进入PPO回报、损失或优势；**不能靠加大这段reward训练出更好的脚本**。前段暂缓普通倒地等终止判据是为允许真实翻身，机械越界与闭链断开始终有效，脚本超时仍失败。

完整链分别记录脚本、混合、接稳、后续动作。到了关节目标、进入RL、曾短暂稳定、连续稳定和恢复后完成动作不是同一成绩；脚本失败、接管判定错误与RL跟踪误差分开归因。失败分母保留，不能只统计已经翻正的子集。

当前评分采用真实双轮支撑、无不允许接触、带符号朝上（12°内）、roll/pitch角速模小于0.75rad/s、站高偏差不超过5cm。运动解锁前需低速且连续1s稳定，之后连续1s满足后续命令（前向误差≤0.12m/s、yaw误差≤0.2rad/s，站立还需平移速度<0.10m/s）。非平地还必须保住所声明的顶面支撑和前进位置，掉到低地再站稳不能通过。此为恢复链专用判定，不能冒称满足普通静站1cm/0.03m/s精度门。

旧的全回合height/tilt/速度MAE不用于判罚恢复前段；原始误差仍保留诊断。每个请求回合都必须有完整链证据，无失败或截断、单次混合交接、纯RL稳定和动作成功。S1–S5D每项每seed4回合，S6每项每seed20回合，沿用两个冻结评测seed。当前恢复判据逐回合要求通过，不把小样本通过率称为高置信可靠性。

S3起既有质量/COM、摩擦、气簧/驱动强度、持续单侧降额及通信抖动/丢包随机化随同一episode贯穿脚本、混合与RL，不在交接时重抽或清缓存。它们仍是各自合同声明的工程扰动域；既有固定评测的扰动案例不等于26姿态×全部扰动的交叉验收。腿侧全构型响应、温度/老化/持续泄压仍未通过辨识。
