## 2. 控制分工和必须对齐的时钟

目标链路为：真实观测选择恢复路线 → 脚本产生协调连续参考 → 反馈控制翻正/捕获 → 满足可部署支撑条件 → 200ms模型侧力矩混合 → RL零速稳定保持 → 放开运动/跳跃请求。

- 脚本承担大范围翻身，RL学习可达接管状态的稳定与后续运动。不能把平衡策略任意角度reset后要求其代替未实现的翻身轨迹。
- 同侧髋、膝主动轴协调；连续共同圈数和闭链分支必须保留。主动轴无位置止挡不意味着相对膝或气簧无限行程。
- 当前 RMCS `rl_controller.cpp` 的 `pd_divisor=rate/200`，非计算tick重发旧力矩。**1kHz执行器循环不等于1kHz PD。** 迁移目标为恢复FSM/参考更新200Hz、下层PD/P及力矩混合1000Hz、RL目标50Hz。先分离时钟，再逐拍比对；不能简单改除数并把全部状态机计时加快5倍。
- 脚本与RL各自保持目标，混合的是模型侧力矩；下行延迟/丢包、执行器响应及输出约束在唯一共同输出路径作用一次。影子推理、上一动作、slew和反馈年龄按实际RMCS语义保留。
- 复用 RMCS 原生 `recovery_controller/recovery_observer`，以小型仿真适配器提供反馈和接收目标/力矩，不复制新的第三套恢复状态机。旧Python脚本作为对照，不能用其成功替代C++闭环。
- 新V6轮侧已验证响应贯穿脚本、混合和RL；腿侧未qualified仍标工程先验，不能把PD整定或悬空bag等同于全构型负载模型已辨识。重力、真实气簧机构力矩与止挡接触在三段连续存在。

只读源码复核还发现两个实际移植点：旧 `inspect_v5_activation.py` 直接写入joint effort并保持多个物理子步，绕过现训练的command transport/actuator response；旧Python `recovery_observer.py` 仍有V5的 `theta0=π−2.3573`。新适配器应复用正式环境的单物理步执行链，并从当前V6闭链求解/LUT生成几何，不靠增加physics_substeps或替换URDF路径宣称迁移完成。

## 3. 先生成可达状态，再教接管

复验完整14姿态矩阵：正立、低蹲及两类释放、左右侧翻、前后45°、前后90°释放、四类前后劈叉镜像。再复验五种200mm台阶异常姿态；将200+250mm双级后的接管状态作为后续专项留出，不能据旧20cm测试宣称已覆盖45cm顶面。

每条回放从满足闭链和合理接触的初态开始，恢复途中不直接改根姿态或关节状态。保存脚本捕获末段、混合开始、混合结束和运动解锁附近的连续记录；失败记录保留，用于区分脚本未到达可接管状态、接管判定错误和RL接稳失败。

接管状态记录至少包含：

|类别|记录与恢复要求|
|---|---|
|物理状态|根位姿/线角速度、完整主动与被动关节q/dq、轮角及共同圈数、闭链装配分支、气簧状态、实际地形与接触布局|
|控制历史|脚本路线/阶段/参考/计时、各自PD目标与参数、影子RL目标、上一action/target、slew历史、混合权重、稳定驻留与运动保持计时|
|动态与通信|执行器响应内部状态、待发/已到/保持力矩、CAN相位、延迟队列/时间戳、反馈缓存与年龄、观测器滤波/探测状态|
|随机化与身份|质量/惯量/COM/摩擦、气簧与降额参数、扰动组/种子、资产/源码/控制/模型/轨迹SHA及生成策略身份|

物理后端的接触求解器内部状态不能凭q/dq完全复原。优先通过保存的短段控制前史重新构造接触和缓存，再核对混合起点的姿态、速度、载荷与输出一致性；未通过恢复等价性检查的快照不进入接管库。

跨动力学参数或策略改变后，不原样复制旧状态库的隐藏控制状态。用相同初态与扰动配置重新跑脚本/前史生成该合同下的接管分布。训练与留出按完整轨迹、种子及姿态分组，禁止随机拆相邻帧造成泄漏。

现 `env.reset` 会清除动作、反馈历史和通信/响应缓存，尚无完整接管导入接口。`UsbCommandTransport.tick` 是全batch时钟：单环境导入必须将事件时刻和年龄转换到接收时钟，不可回退全局tick；随机流同样不得为一条接管样本重置整个batch的RNG。状态定义明确根link姿态与COM速度参考端，避免把两者当同一参考点。

接管5%内按姿态家族分层，在已验证可达的范围内提高历史薄弱类权重。具体权重由生成记录的覆盖率冻结，不使用无效快照填满配额；有效状态不足时报告coverage缺口，不静默退化为普通stand reset。

混合阶段不能把实际执行的“脚本与策略加权力矩”伪装成纯actor动作。首版PPO从完整混合结束且物理/控制前史已恢复的可达状态开始；200ms混合和其前后仍以当前候选策略跑完整链固定评测。若以后训练混合阶段，必须显式表示可部署相位并正确存储策略采样及log-prob，不能直接混入现有普通rollout。

接管后仍以零速/目标站高稳态为起点，满足实际1s保持条件后再给连续运动命令。actor不读取世界接触/恢复库标签；网络形状保持35/81，新增语义若需要占用原槽也须单独冻结和验收。

## 5. 稠密奖励、随机化与分项验收

脚本段无PPO奖励；RL接管段复用广域＋精核的站高、姿态/角速、平移/轮滑、动作连续性和功率成本。奖励从实际支撑恢复平滑过渡到站高/零速跟踪，不强迫仍由壳体合法承托的过渡姿态瞬间达到标准站姿。真正开始PPO的状态必须符合声明的可接管域；深度倒地、脚本超时与非法支点不通过宽限fall逻辑隐藏。

接稳后以运动请求跟踪检验控制权真正交接；“到了目标关节角”“曾进入RL”“曾短暂稳定”“末尾稳定”“恢复后继续执行任务”分别记录。精度未达标单独标注，不统称完全不会自起。

质量/COM/惯量、摩擦、气簧/电机强度与同合同通信抖动/丢包应贯穿完整恢复链，并在单次回放内保持一致。先名义、再单因素、再未训练组合；支撑估计误判须有专门案例。悬空辨识中的有效参数与未辨识参数明确区分，不声称温度/老化已覆盖。

完整能力交付需要两层结果：

1. **脚本层**：逐姿态到达可接管域的比例、耗时、止挡/气簧/碰撞、力矩与速度约束、支撑误判；脚本不能到达的类别不能归因成RL训练失败。
2. **接管层**：200ms混合连续性、至少1s且连续稳定1s后才解锁、随后运动命令跟踪、漂移/跌倒/重新失姿；每姿态、每种子独立统计，完整链成功不能只按条件于“脚本已成功”的子集计算。

先复现14×5与5×5名义矩阵并固定两个评测seed；最终扰动验收的重复数和阈值随新合同冻结。S6总报告增加必需的R0完整链覆盖检查：缺测试/缺接管库/仍有未声明的失败域，状态为能力范围未完成，不能显示“完整课程全部功能已交付”。当前合同尚无此检查，文档补齐不等于门已经生效。
