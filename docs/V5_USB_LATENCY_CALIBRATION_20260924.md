# USB-HS回环测量如何进入sim2real

用户确认：所给数字是回环RTT，实际部署使用USB-HS。10k warmup＋100k sample，
CPU隔离、xHCI IRQ与benchmark同核、SCHED_FIFO priority 80，活动抢占模式为voluntary。
完整原始分位数和环境保存在`docs/evidence/usb_loopback_20260924.json`。
训练输入先验保存在`contracts/v5_usb_latency_prior_v1.json`，由V5.9完整训练合同显式载入。
运行组件为`src/wheeled_tasks/chassis/usb_transport.py`；该profile本身不是独立训练合同。

## 1. 数据结论

| HS size | p50 RTT | p99 RTT | 本次最大RTT |
|---|---:|---:|---:|
| 4 | 79.878μs | 82.423μs | 161.866μs |
| 32 | 79.736μs | 84.069μs | 163.576μs |
| 63 | 79.688μs | 83.893μs | 163.846μs |

测量呈现约0.080ms中位数、0.082–0.084ms p99、约0.164ms已观测尾部。
三个尺寸的HS结果接近，但不得据此外推任意消息长度、并发负载或不同调度环境。
FS作为另一种硬件模式保留，不与HS随机混合成名义分布。
100k样本的最大值不是物理上界；未获得原始序列，不能声称已辨识罕见尾部概率或时间相关性。

这替代了“USB本身约3–6ms”的估计，不代表整个机器人闭环仅有80μs：
传感器采样／滤波、控制线程相位、MCU电机总线调度、驱动响应仍未包含或尚未分离。
ONNX耗时测试与此回环测试也不是同一段端到端负载测量，不能简单相加后宣称完整闭环已标定。

## 2. RTT不能直接当两个方向各自的延迟

回环大致包含下行、设备回环处理、上行及计时路径的软件开销。
方向拆分与设备处理耗时目前未辨识。RTT/2只能作为对称假设，不是单程测量结果。

初期诊断可共享一个采样RTT预算D，用αD与(1−α)D分配到有效回传／下发通道，
α取0.25、0.5、0.75进行敏感性比较。这把未分离的回环处理开销吸收为有效传输预算，
不是上下行单程延迟的物理辨识；后续用真实控制协议时间戳替换。
不能在反馈和下发各放一个完整D，也不能把同一反馈在actor与PD里重复延迟。

## 3. 随机化先验

按实机消息尺寸显式选择HS profile。现有分位数可构造分段线性的逆CDF近似：
概率节点0、0.5、0.95、0.99、1对应本次min、p50、p95、p99、max。
区间概率质量与给出的分位数一致，但区间内均匀密度是工程假设，尤其下半区与最后1%并未被原始数据辨识。
它不是经验CDF，不应从中推断真实均值、丢包率或相关抖动。
拿到原始逐包CSV后优先使用经验采样／连续轨迹回放，同时保留实际包序相关性。

优先先做固定分位点评测，随后在短预算适应训练中混入该近似先验。
额外0.2、0.5、1ms RTT作为明确标记的压力测试，暂不混入“实测名义”分布。
本profile不改变50Hz策略，也不把主动电机通信时延施加到被动气簧。

## 4. 亚物理步时延

当前策略周期20ms，物理／PD周期5ms。约80μs RTT仅为0.016个物理步；
直接启用现有策略步延迟会得到0/20ms，向上取一物理步又变成5ms，分别约为中位RTT的250倍和62.5倍。
按四舍五入则几乎全部归零。即便改为1ms物理步，80μs仍是0.08步。
按均值匹配偶尔跳过一个整步也不等价：它制造了原测量没有的5ms或20ms尾部。

因此不能将这批数据直接填入当前`max_delay_steps`。需要亚步表示：

- 反馈：带时间戳的历史状态，在所需过去时刻重建模拟测量值；可先使用短时线性插值近似。
  使用的数据时间不得超过控制时刻；插值是传感器仿真近似，不是部署端读取未来反馈。
- 下发：PC-PD计算力矩后延迟其生效时间，保留前一力矩直到新指令到达。
  对δ小于物理步长Δt的单次切换，可先以
  `tau_average=(δ/Δt)*tau_previous+(1−δ/Δt)*tau_new`近似一步内的力矩积分。
  这不是简单对动作目标做低通；遇到多次到达需按区间分段积分。
- 平均力矩近似对接触／饱和等非线性过程并非精确，应以少量环境的高时间分辨率执行结果做对照，
  达到可接受误差后再用于大批量训练。不要为80μs链路把所有环境永久改成数十kHz物理步进。
- 1kHz PD与50Hz策略仍可独立选择；小延迟本身没有提供把策略改为100Hz的必要性证据。

## 5. 下一轮纳入顺序

1. 完成232mm新资产上的候选选择，建立50Hz名义基线。
2. 确认实际控制消息尺寸与USB API计时起止点，优先回收逐包序列和负载条件。
3. 实现共享反馈与力矩下发的亚步时序组件；零延迟回归、时间单位、同包相关性、reset、hold-last均需测试。
4. 固定策略比较HS中位、p99、观测尾部及工程压力点，先判断对任务的敏感性。
5. 小预算渐进训练，保留clean任务样本；USB按实测尺度，电机总线／采样滤波等按各自证据单独建模。

已实现亚步通信组件：每个物理步重新采样RTT以产生时间波动；上下行比例按episode采样，二者共享同一RTT预算。
初始阶段约50%环境启用，后续约70%；保留零通信扰动环境。actor与PC-PD共用延迟编码器反馈，
下发作用于PD之后的力矩；气簧不进入通信队列。TensorBoard记录秒制延迟、μs制均值／峰值及启用比例。
逐步独立抖动与区间内分布仍是近似先验，不把统计表解释为已测得的逐包时间序列。
