# V6 整腿联合辨识与训练接入方案

日期：2026-09-28 晚间。已汇总11个开发/整定bag：左右腿选160/2.5，轮侧选0.6/0/0；右侧新增益完整161段且跟踪改善，双侧复核待完成，物理模型尚未通过跨引擎验收，未发布到训练。详见[bag清单与判决](V6_BAG_SUMMARY_20260928.md)、[完整训练计划](V6_NEW_ASSET_TRAINING_MASTER_PLAN_20260928.md)。0.4轮包尾部截断，仅用于合格窗口比较。

**本轮目标是50Hz策略/目标、1000Hz PC纯PD/P的执行器闭环辨识。** 腿部`tau=Kp*(qref-q)-Kd*dq`，DM内部Kp/Kd为零，无积分和速度/重力前馈。已有正式训练与RMCS RL链仍需从200Hz路径迁移。早期位置P＋速度PI包只能按归档控制器解释；新PD整定结果与被控对象拟合资格分开。

用户确认：尺寸不变，气弹簧全伸销距232 mm、行程80 mm，轮侧减速比15.8；腿侧辨识对象是带连杆和气弹簧、同侧两个电机同时工作的完整机构。四腿电机经1:1外部链传动驱动两个独立主动轴；六轴均由PC计算力矩，DM使用模式A。

后续确认：USB使用HS模式、亚毫秒延迟。已存[回环测量](V5_USB_LATENCY_CALIBRATION_20260924.md)为RTT，p50约80μs、p99约82–84μs、样本最大约164μs；使用该来源明确的先验，真实控制负载、上下行拆分、CAN等待与电机响应另行核对，不沿用0.1–5ms作为USB实测名义范围。

## 1. 辨识的系统边界

采用华南虎[文章4.2的整腿real2sim方法](https://bbs.robomaster.com/article/1942489?source=1)：实机架空执行预设轨迹，在MuJoCo中复现同一轨迹、控制器和机械装配，联合比较两个主动轴响应。不是拆下电机分别拟合两个互不影响的传递函数。

两个电机的编码器可以独立线性映射到两个主动轴，机构动力学仍是耦合的。闭链几何、连杆质量/惯量、重力和气弹簧会共同影响两轴响应；运动学映射为对角矩阵不等于动力学解耦。新资产轴向和旧资产不同，必须先确定bag使用的编码器零位/符号与新模型的映射，不能用优化阻尼掩盖符号错误。

使用完整闭链模型后，刚体惯性、重力和气弹簧的几何耦合已经由物理引擎产生。联合辨识首先拟合该系统的少量未知参数，不默认再叠加一个任意“耦合力矩矩阵”，避免重复计算已有动力学。链传动柔性、间隙、方向相关损耗等只在留出轨迹存在稳定残差时增加。

## 2. bag的数据合同

保留原包，解析后统一到SI单位与模型主动轴坐标，并记录原始字段、转换公式和数据哈希。ROS1 `.bag`、ROS2 `.db3/.mcap` 可以通过解析层统一，当前字段及消息schema已随包归档，见bag清单。

|数据|用途与缺失影响|
|---|---|
|两主动轴目标角、目标角速度、轨迹ID/开始时刻|复现共同输入；只有实际角度，不能重建真实闭环输入|
|两轴原始编码器q/dq及反馈时间戳|对齐跟踪误差、相位滞后和跨轴响应；保留解缠前原始值|
|PC计算力矩、限幅后实际发送值、发送时间|区分控制器、传输和驱动器误差，不能只保存位置目标|
|反馈电流/电机报告力矩及其时间戳（若有）|约束增益、限幅和响应动态；电流换算值不是独立测力传感器真值|
|Kp/Kd、控制模式、控制/反馈周期、滤波、限流|作为真实控制链配置冻结，不能在拟合中随意调Kp去补机械误差|
|轴顺序、零位/方向、反馈参考端、传动比、软件/固件版本|防止电机转子、减速后输出轴、相对膝角混用|
|实机姿态、固定方式、装配版本、弹簧/轮子是否安装、初始构型|仿真复現相同重力和边界条件；软吊挂不能直接当绝对固定基座|
|电压、温度及重复试验编号（若有）|区分漂移和稳态参数变化，确定随机化范围|

不逐条曲线任意平移时间或做动态时间规整来获得“漂亮重合”。先校准时钟，再用共享且有物理意义的时延参数拟合。不同步的接收时间与设备采样时间需要分别保留。

若只有q/dq和目标，也可做有效闭环模型拟合，但力矩比例、摩擦、惯量和时延可能互相补偿。届时应报告可辨识的参数组合与不确定性，不把每个拟合值都当成唯一真实物理参数。

## 3. 轮电机：摩擦/阻尼与力矩包络分开

轮子架空，使用双方向低速起动、匀速台阶、加减速与滑行段，联合约束静摩擦/起动力矩、运动摩擦、粘滞阻尼以及必要的有效惯量。正反方向和不同转速都需要覆盖。仅凭一条匀速曲线不能同时识别所有参数，只有无载转速响应也不能确认满载力矩包络。

运动时可先用轮输出端模型：

`J_eff * domega/dt = tau_drive - tau_c * sign(omega) - b * omega`。

零速附近另处理起动/粘着阈值；简单`tanh(omega/epsilon)`只是平滑近似，不等于已识别真实静摩擦。只有数据显出必要性时才增加Stribeck或方向不对称参数。这里识别的是电机/减速器/轴承的关节损耗，地面摩擦、轮胎滚阻和打滑另做接触验证。

策略仍输出轮端rad/s。15.8只在转子端与轮端转换时使用一次：转速`omega_motor=15.8*omega_wheel`；驱动侧理想力矩需按相应效率和传动比转换。若提供的曲线已是轮输出端测量，直接以轮端建表，不再乘15.8。DM输出端反馈也不再额外套用其内部减速比。

必须注明曲线的力矩边界：若曲线已是减速器输出端净力矩，其中可能已含传动损耗；再扣同一摩擦会重复。优先保存驱动力矩模型和被动力损耗的明确边界，再接入物理方程。制动/反转象限不能仅凭正向驱动曲线宣称已标定。

华南虎[M3508执行器源码](https://github.com/scutrobotlab/wheeled-legged_RL/blob/b8ff79f3df855faf9dc92f4a282bd80c42649466/source/agent_world/agent_world/actuators/m3508_actuator.py)展示了电机端曲线到输出端的转换与查表限幅；其低速补点、效率和上限是该模型的假设，不是本机实测参数。

## 4. 腿电机：在完整总成上分层联合拟合

保留两电机、连杆、被动关节、轮子及气弹簧，左右腿分别验证。推荐轨迹包含：两主动轴等增量摆动、改变两轴相对角的伸缩、不同相位/频率的联合运动，以及多个构型下的低速往返与停留。只有两轴始终同相同幅的轨迹容易让参数混淆，不能完整激励伸缩自由度。单轴变化、另一轴保持可作为总成内的辅助实验，不替代联合运动数据。

拟合顺序：

1. **几何与数据对齐**：固定新资产质量、惯量、闭链拓扑和轴映射的可信值，复现装配、固定姿态及初态。84g/840g之类十倍差异先解决，不能丢给优化器自由补偿。
2. **低速/停留段**：检查气弹簧预载和力—行程曲线、静态偏差、起动摩擦及方向差异；本轮先固定既有气簧名义拟合；若需要调整气簧残差，应另立有约束消融并报告与摩擦的相关性。
3. **联合动态段**：在上述约束下拟合输出端有效armature、主动/被动关节阻尼和摩擦，以及数据能支持的力矩比例修正。参数少量、分组、有非负/合理范围约束；不一次释放每根杆的全部惯量和每个铰的所有参数。
4. **响应与高负载段**：检查通信时延、反馈滤波、驱动力矩响应时间、饱和/超调。只有出现相应残差才从纯时延/一阶响应升级为更复杂模型。架空低负载bag不能证明跳跃时峰值力矩、供电能力和热限制已识别。
5. **剩余结构误差**：仅在不同轨迹重复出现时加入气簧压缩/回弹滞回、链传动柔性/间隙等。缺少测量时保留有效参数集合，避免对单个物理元件作过度解释。

每次候选参数都同时计算两轴的q、dq误差、相位差、交叉响应；力矩/电流可信时加入其误差。使用按测量噪声/轨迹幅值归一化的稳健损失，并对偏离CAD/实测先验增加正则。两轴联合损失不能让一轴的高精度抵消另一轴明显错误，验收还要看各轴最大值/分位数。

MuJoCo里的“回放真机数据”用于参考轨迹、输入重放和叠图比较。仿真状态从相同初态自由演化，不能每帧把实测q写回仿真后宣称动力学拟合成功。优先同参考、同PC控制器的闭环复现；有可信发送力矩时，再用较短的力矩输入重放交叉验证，区分控制器误差与被控对象误差。

## 5. 接入现有训练链的位置

当前代码实况：

- `src/wheeled_tasks/chassis/v5_control.py::motor_efforts`：四腿PC PD后±40Nm限幅；轮速P控制后使用旧轮包络。
- `V5Control.spring_efforts`：仅压缩量对应的静态三次力曲线，没有实测滞回/速度项。
- `src/wheeled_tasks/chassis/env.py::step`：使用可能延迟的反馈算力矩，再叠加motor_strength和传输，写入主动关节；气簧力单独施加。
- `src/wheeled_tasks/v40/core.py::motor_torque_limit`：只接受电机端曲线并做传动比换算，暂不支持已测轮端曲线的明确分支。
- `src/wheeled_tasks/chassis/motor_envelope.py`：独立的研究性恢复包络，不是已接入主训练的实测执行器，不能只修改这里便认为主线生效。

建议新增一个版本化的执行器/机构辨识配置，由MuJoCo适配层和Isaac适配层共同消费；保留当前策略目标语义：

```text
策略：四主动轴目标角 + 两轮目标速度（50Hz）
  → 实测反馈时序 + 同实机PC控制器/限流逻辑
  → 指令传输、驱动响应及瞬时速度—力矩限制
  → 主动轴驱动力矩
  → 完整闭链刚体 + 关节被动力 + 气弹簧
  → 传感器采样/滤波/上行时序
```

实际限幅位置可能同时存在PC软件端和驱动硬件端，要按记录的真实链路实现。摩擦应作用于真实轴速度，不能因为PC反馈延迟就用延迟速度计算物理被动力。力矩响应模型和通信延迟各自有状态，不再把二者全部揉进一个motor_strength乘数。

气簧由滑动副施力或按虚功映射到主动轴，两种实现选择一个；不能两边同时施加。同理，已经写入引擎的被动阻尼/摩擦不要再在自定义执行器中重复扣除。MuJoCo的`damping`、`frictionloss`和`armature`各有不同物理语义；不能直接把`frictionloss`数值写进另一引擎名称相似的无量纲摩擦字段。[MuJoCo参数说明](https://mujoco.readthedocs.io/en/stable/XMLreference.html#body-joint)

记录“原始命令→发送力矩→驱动输出→被动力→净广义力”各层，力矩上限检查针对电机输出，而不是把气簧/关节被动力也计入电机40Nm预算。源代码中的旧固定damping、motor_strength随机化、USB时延都需要与新参数明确替代/保留关系。

## 6. MuJoCo拟合后必须过Isaac复现

MuJoCo参数拟合良好不代表PhysX中的同名数值等价。用留出的整段bag，在MuJoCo、Isaac分别执行同一参考/控制链，对比两轴误差、时延、反转、闭链残差、弹簧行程与耗散能量。闭链约束和被动力由引擎求解，转换正确性必须通过响应验证。[MuJoCo动力学说明](https://mujoco.readthedocs.io/en/stable/computation/index.html#general-framework)

已有一个具体差异：旧MuJoCo模型默认给所有关节damping=0.002，而PhysX正式`monitor_applied_effort`路径的主动腿/轮damping为0，被动铰与气簧为0.002。拟合前必须对齐最终运行值，不能仅核对配置字段。MuJoCo旧模型步长为0.5ms，正式Isaac为5ms，这个差异也应纳入回放比较。

正式旧课程物理200Hz、策略50Hz；当前USB模块的1ms下行时钟是力矩脉冲近似，不代表1kHz新反馈闭环。辨识先按实机采样和控制周期高分辨率复现，再比较200Hz训练近似是否保持观测到的响应。若显著动态发生在5ms内部，要验证精确离散/子步模型或提高物理频率，不能拿一个被拟合出的“小于dt的时间常数”直接显式积分。

传输RTT、传感器反馈延迟、驱动内部响应三者不可重复计入。时间对齐只能辨出总时延时，配置标成有效合成时延，不伪造上下行/FOC各自精确值。

训练/验证按完整轨迹和采集轮次分割，不能随机拆相邻采样点。拟合若只能重现一条正弦，不通过新频率、新幅值、新构型、反转、不同负载，则不进入正式训练。误差阈值在看到重复测量噪声和任务精度预算后确定，当前不编造“已达到”的角度或力矩精度。

## 7. 从辨识结果到随机化与新课程

输出包括名义参数、适用速度/负载/温度范围、参数相关性、留出误差和未辨识项。随机化以多个重复试验支持的参数集合为中心，保留相关性；不要给摩擦、惯量、时延、弹簧力各自随意±20%，组合出没有实物依据的系统。左右装配差异保留，质量/弹簧力/惯量不得逐帧乱变。

**温度/老化的明确范围：本轮仅验收已记录的名义温度条件和当前装配、使用状态。** 电机及驱动器热降额、气弹簧温度依赖，以及长期泄压、密封/轴承/链传动磨损与老化均未建模。结果不外推到未覆盖温度、连续热负载持续时间或寿命阶段；未建模不等于无影响。现有气簧目录插值和速度—力矩包络不构成热模型证据。

每段bag记录环境温度、各电机/驱动可用温度通道及测点、左右气簧筒表面温度；壳温不冒称绕组温度或气体内部温度。并记录静置/预运行历史、连续运行时间、供电与负载、冷却条件、热告警/降额状态、部件标识和维护/更换/补气记录；运行小时与循环数未知则填未知。试验前后重复基准轨迹，比较高度、行程、力矩与往返迟滞。缺温度记录时标为“热条件未追踪的条件性结果”，不填假定25℃。

`thermal_valid_domain`只填写实际覆盖的温度×负载×持续时间组合；未覆盖项保留未验证。温度重复试验支持相关参数变化后再纳入不确定性集合，不任意加一个独立温度倍率。维护、更换或基准响应超出重复测量误差时重验相关项；本轮不编造长期老化分布或固定寿命周期。

先检查标定名义模型中的完整目标域可达和基本策略可学，再逐步加入已测不确定性、接触与更复杂技能。架空辨识不识别地面摩擦、打滑和落地碰撞，后续单独验证。重新计算不同高度和速度下的支撑/起跳余量，决定动态参考的速度与加速度，而非照搬上游轨迹常数。

此流程解决sim2real动力学差异；历史中同一仿真资产上的能力退化仍需独立修正采样、奖励和阶段验收。新资产和辨识模型改变动力学合同，不能声称旧checkpoint是无语义变化的exact resume。兼容时可作显式迁移，是否继承critic/Adam要作为实验变量记录。

bag到达后的产物：数据质量/参考端审计、MuJoCo联合拟合结果、留出轨迹验证、Isaac跨引擎回放验证、版本化参数与随机化配置。满足这些条件后，再按仓库要求提交代码/合同/计划，从冻结commit部署到Kaiser的tmux任务。
