## 4. 覆盖与reward冻结

- flat：25%静站（九档各2%固定，共18%，另7%连续）；15%升降；25%平移；20%启停；15%正反yaw。运动三池各半数名义305mm、半数跨完整高度采样，补齐高度×运动联合覆盖。静站20s覆盖10s漂移窗口。
- recovery：65%脚本接管、15%推扰／腾空／落地、20%基础保留；speed：60%运动、20%启停、15%静站、5%升降。
- terrain：60%上下阶、20%坡／粗糙／材质迁移、20%基础；jump：65%原地／行进跳、15%请求序列、20%基础；stepjump：50%单阶跳、25%双阶跳、5%平地跳复习、20%基础。
- 非flat域的20%基础为九高度各1%、连续静站6%、低速进出5%；正反向按已有配对spec分配。高度连续分布增加边界密度；地形由场景组与命令spec绑定，不全域随机混搭。
- 运动命令驻留1–8s，20%长尾8–15s；启停先真实零速等待0–8s再走完整序列，打散制动相位。跳跃请求间隔0.5–4s，重复／取消分布保留。
- fixed LR=1e-4，完整保留actor/critic/Adam，跨任务无重复critic预热。网络35D/81D及既有dense reward原权重不变；保留普通静站无落地bonus、显式落地仅0.6s零中心成本的已验证修复。评测分数不是训练reward。
- 跳跃辅助按本域actor时钟0–300衰减力度／概率，评测始终无辅助。v2的3/6/10/15/20/25/30cm分箱概率按本域actor时钟线性插值：0次为30/25/20/10/5/5/5%，2000次为10/15/20/20/15/10/10%，6000次及以后为5/5/10/15/20/20/25%。不依赖评测通过，低档始终有至少5%复习；原地与行进单跳均采用此表，固定评测和预设台阶高差不被重采样。SCUT提供迭代范围课程与静态bins；本表是本项目设计，不冒称为其已运行的概率表。新域课程时钟从0开始，故障恢复从封存时钟恢复，绝不将父模型的上万步谱系直接当作新跳跃课程进度。
- USB亚毫秒延迟／抖动／丢包、载荷／质心／接触随机化完整继承；flat不引入额外边缘出生／持续单侧降级，后续域各5%。这些是冻结工程不确定性，不声称已由实测精确辨识。
- 保留20k环境、50Hz策略、1kHz物理与PC PD、160/2.5、已验证轮侧响应和气簧模型。未qualified的四腿响应bag不得称为已接入；更换动力学需新合同与复习验证。

## 5. 不反复启停的执行方式

`run_task_campaign.py`顺序执行六条线，同一域由一个常驻`train_chassis.py`运行，episode、物理场景和PPO连续。每次attempt首个PPO及每500消费更新封存不可变快照；不再每40轮销毁场景。

v2按最新用户要求设置`execution_mode=uninterrupted_cap_then_next`、`evaluation_interval=0`。训练进程不创建周期评测请求，不等待分数、不按成绩提前结束、不自动回滚。每域的20k消费用满后封存研究候选，并直接开始下一任务域；每域只为初始化新场景启动一次worker，故障或明确版本迁移另记attempt。训练完的状态是`domain_budget_exhausted_unassessed`，`domain_qualified=null`，不能把“跑完”写成“通过”。

固定评测定义和阈值完整保留，独立执行`run_task_campaign.py --evaluate-only`才产生分项结论；该入口与训练共享排他锁，不能同时抢占本次GPU。日常观察TensorBoard的分项行为误差／存活／接触／饱和／课程覆盖，以及需要时在独立资源播放已封存模型。reward上涨仅为过程证据。终点评测可确认qualified，但不会倒过来改变已经消费的预算或触发训练重跑。

预算源目录持久共享账户与flock排他锁禁止重复启动。每个optimizer更新前持久预留消费；故障不确定更新照计，回滚不会退款。故障从最近合法完整checkpoint续训，已丢失的谱系和已消费的预算分开。已有活worker不能再启动第二个。源码／合同／计划先提交、再从commit归档部署；禁止热改。

我方4096更新的原始策略转移数约等于SCUT20k更新，但更新次数、轨迹相关性、优化分批和物理动态不同，不能据此宣称同等学习质量。每域20k按最新授权连续跑完，固定评测不再控制停止时机。

v2合并部署两项运算等价优化：六轴交错布局用基础切片视图替代反复高级索引，返回力矩仍每次独立分配、保留原限矩运算顺序；没有USB延迟反馈时复用同一物理子步已计算的轮速力矩包络，有USB延迟则仍按当前物理速度重新计算。有限值检查、求解器、时间步、执行器响应及奖励数值不变。CPU逐值／多步／正负零与污染检查见performance/v5_control_cpu_equivalence_benchmark.json；CPU微基准不是整机加速承诺，部署后的Timing/env_step_seconds与wall_seconds才用于更新ETA。进一步同步／融合／求解器优化须另行验证后冻结。64/32来自历史工厂继承，尚无证据证明是当前V6的最低必要值；后续32/8、SCUT12/6等候选需同模型整车验证，旧V5／架空轮台架成功不能替代。结构与来源证据见 `reports/v6_task_campaign_20261001/performance/solver_and_model_audit.json`。60策略步工程探针约110.7秒；其cProfile只覆盖12.1秒、缺少关键父调用，不能把部分profile比例当作完整瓶颈证明。

### 6.2 10月2日dt复核与粗步长训练候选（未部署）

最新远端TB最近50更新约45.1s/轮，env.step约43.9s、optimizer约0.254s；此前仅3个稳定样本显示43s不能视为持续4.6%提速。仍在flat连续PPO，评测等待0。原始配置与这次实时统计在performance/dt_audit_20261002.json。

我方physics_dt=1ms/decimation20，SCUT实际flat归档5ms/decimation4，二者策略20ms/50Hz、rollout24相同。加上环境20k对4096，每轮原始物理环境步分别960万与393216，数量比24.414；这不是墙钟倍率。慢的一项结构原因是我方dt更小，不能以继续减小dt来加速。64/32相对12/6的求解成本另行测试，不能将比值直接乘入ETA。

工程候选是把大规模训练与1kHz辨识/验证分开：50Hz策略及20k不动，先在相同模型、控制参数与64/32求解器下对比1/2/5ms；验证闭链间隙、气簧深压缩、力矩/跟踪、碰撞穿透、落地/起跳和通信短丢包的动态差异，再决定能否采用5ms训练，或2ms折中。选定dt后才单独评估32/8及12/6求解迭代。高频参考使用相同预设轨迹/封存策略，工程探针不新增PPO预算；不与当前训练抢同一GPU，当前未启动探针或改合同。

实车PC PD及新bag仍保持1kHz，参考50Hz。训练5ms若每次物理刷新才算PD，则模拟反馈PD为200Hz；现有通信模块的5个1ms内部tick只保持同一输入，不能声称实现了5次新反馈闭环。粗步长须冻结为新的近似控制合同，重审响应模型/通信冲量/峰值接触/奖励时间单位和恢复脚本计时，不能只改physics_dt或绕过1kHz断言。以1ms回放检查迁移误差，必要时保留1ms的瞬态训练域。未qualified腿bag仍不标为已接入。
