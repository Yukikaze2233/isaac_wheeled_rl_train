# 实际俯仰奖励参考核查

冻结运行源码 `b4ce80964d47`、speed v14 合同的 `reference_reward.visible_reference_only=true`。软件参考模块虽计算 `atan(ax/9.81)`（限幅 ±0.15rad），实际 `reference_motion_terms` 在这个开关下覆盖该参考：普通 `terrain_mode=0` 的目标为 **0rad**；可见的特殊台阶模式在前4秒使用命令符号×0.08rad。v14新增姿态平方成本下限沿用这个实际目标，不能描述成已经跟踪加速度俯仰参考。

这是连续的软成本，没有强制改写车体角度。不过，加速时合理倾斜也会支付该成本；“不是硬约束”不等于“已有加速度补偿”。35D策略没有单独加速度观测，不能未经观测一致性检查直接翻转开关。普通底盘搭台收腿模式仍是terrain_mode=0，不自动享有特殊台阶模式的倾角豁免。

`audit_reference.py` 从git读取实际冻结函数和合同，在CPU对20个构造状态执行支付反事实及逐值断言，没有复制近似奖励、启动Isaac/PPO或修改运行配置。例如3m/s、参考加速度+1.5m/s²时，软件参考限幅为0.15rad（8.59°）：

| 车体俯仰 | 实际三项俯仰奖励密度 /s | 假想启用加速度参考 /s |
|---|---:|---:|
| 0° | 1.000 | -0.075 |
| 8.59° | -0.075 | 1.000 |

三项为pitch_exp、pitch_velocity和locomotion_pitch_floor。表只揭示参考支付方向，不证明8.59°是完整闭链机器人的最优姿态，也不能预测PPO学习结果。关闭visible_reference_only只是反事实，未部署。

旧flat使用相同visible参考却具有较好低速姿态，故该开关不能单独解释新speed退化。后续若调整，应保留静止与匀速水平目标，分别检查加速/制动的实际pitch、轮力矩饱和、跟踪和停车，处理延迟观测下的参考可见性；冻结新合同后才能进行训练对照。

证据为 `reference_counterfactual.json`。本次只修正审计表述，不热改正在训练的v14合同，也不授予行为或实车资格。
